# 8.2 用户新增：从密码策略到完整的服务端写入流程

上一节我们完成了用户列表查询，已经可以按照关键词、状态和分页读取用户数据。

接下来实现用户新增。表面上看，只需要增加一个弹窗和一条 `INSERT` 操作，但用户管理与普通业务数据不同：用户可以登录系统，密码的处理方式直接影响整个系统的安全性。

本节按照项目现有的分层结构，依次实现：

1. 定义用户新增和密码校验规则。
2. 实现密码哈希处理。
3. 实现用户创建 Service。
4. 实现 Server Action。
5. 实现使用 shadcn/Base UI 组件的新增用户弹窗。
6. 验证新增流程及异常情况。

本节只实现新增用户，编辑、删除和重置密码分别在后续小节实现。

## 一、明确新增用户的业务规则

首先确定用户新增时需要填写哪些字段。

| 字段 | 是否必填 | 规则 |
| --- | --- | --- |
| 用户名 | 是 | 3～50 个字符，字母开头，只允许字母、数字、下划线和连字符 |
| 姓名 | 是 | 去除首尾空格，最长 100 个字符 |
| 邮箱 | 否 | 非空时必须符合邮箱格式 |
| 手机号 | 否 | 非空时校验格式 |
| 初始密码 | 是 | 12～128 个字符，拒绝明显弱密码 |
| 确认密码 | 是 | 必须与初始密码一致 |
| 用户状态 | 是 | 只能是 `ACTIVE` 或 `DISABLED` |

用户名在创建后暂时不允许修改。初始密码和确认密码只在创建过程中使用，不会成为用户资料的一部分。

用户创建成功后，数据库保存的是密码哈希，而不是原始密码。

### 1. 密码策略

本项目采用以下第一版策略：

- 密码长度为 12～128 个字符。
- 不强制要求必须同时包含大写字母、小写字母、数字和特殊字符。
- 拒绝常见弱密码。
- 不对密码进行 `trim()`，避免悄悄改变用户输入的密码。
- 使用专门的密码哈希算法保存密码。

密码校验必须放在服务端。前端提示只能改善用户体验，不能代替服务端验证。

## 二、定义用户新增的输入规则

在 `server/user/` 目录下新建 `schema.ts`。

```ts
// server/user/schema.ts
import { z } from "zod";

const commonWeakPasswords = new Set([
  "password",
  "password123",
  "123456789012",
  "qwertyuiop12",
  "admin123456",
]);

export const passwordSchema = z
  .string()
  .min(12, "密码至少需要 12 个字符")
  .max(128, "密码不能超过 128 个字符")
  .refine(
    (password) => !commonWeakPasswords.has(password.toLowerCase()),
    "密码过于简单，请更换一个更安全的密码",
  );

const usernameSchema = z
  .string()
  .trim()
  .min(3, "用户名至少需要 3 个字符")
  .max(50, "用户名不能超过 50 个字符")
  .regex(
    /^[a-zA-Z][a-zA-Z0-9_-]*$/,
    "用户名必须以字母开头，只能包含字母、数字、下划线和连字符",
  );

const optionalEmailSchema = z
  .string()
  .trim()
  .max(255, "邮箱不能超过 255 个字符")
  .refine(
    (value) => value === "" || z.email().safeParse(value).success,
    "邮箱格式不正确",
  )
  .transform((value) => value || null);

const optionalPhoneSchema = z
  .string()
  .trim()
  .max(30, "手机号不能超过 30 个字符")
  .refine(
    (value) => value === "" || /^\+?[0-9 ()-]{7,30}$/.test(value),
    "手机号格式不正确",
  )
  .transform((value) => value || null);

export const createUserSchema = z
  .object({
    username: usernameSchema,
    name: z.string().trim().min(1, "请输入姓名").max(100),
    email: optionalEmailSchema,
    phone: optionalPhoneSchema,
    password: passwordSchema,
    confirmPassword: z.string(),
    status: z.enum(["ACTIVE", "DISABLED"]),
  })
  .refine(
    (data) => data.password === data.confirmPassword,
    {
      message: "两次输入的密码不一致",
      path: ["confirmPassword"],
    },
  );

export type CreateUserInput = z.infer<typeof createUserSchema>;
```

这里有几个值得注意的细节。

**第一，空邮箱和空手机号转换为 `null`。** 数据库字段本身是可空的，统一存储为 `null`，而不是同时混用空字符串和 `null`。

**第二，确认密码只用于校验。** 创建用户时不能将 `confirmPassword` 一起传给 Prisma。

**第三，密码不做首尾空格清理。** 密码中的空格可能是用户有意设置的内容，不能像姓名一样处理。

**第四，弱密码检查只是第一版。** 当前集合用于演示校验流程，正式系统应使用维护良好的常见密码字典或其他适当的弱密码检测机制，而不是认为几条规则就能覆盖所有弱密码。

> 版本说明：以上示例使用 Zod 当前版本的 `z.email()` API。如果项目安装的是较旧版本的 Zod，请根据当前版本改用对应的邮箱校验 API，避免因 API 版本不同而报错。

## 三、实现密码哈希

密码不能明文保存，也不能使用普通的 SHA-256 直接对密码做一次哈希就结束。

密码存储应该使用专门的密码哈希算法，例如 Argon2id 或 bcrypt。

本项目在 7.2 节初始化管理员（`prisma/seed-admin.ts`）和 7.5 节登录验证（`server/auth/verify-credentials.ts`）中已经采用了 Argon2id，依赖 `argon2` 也已经安装。按照优先复用现有实现、不创建两套密码处理机制的原则，这里直接沿用 Argon2id，不再引入 bcryptjs。

新建 `server/auth/password.ts`，把密码处理收敛成统一模块：

```ts
// server/auth/password.ts
import "server-only";

import argon2 from "argon2";

/** 生成密码哈希（Argon2id） */
export async function hashPassword(password: string) {
  return argon2.hash(password, {
    type: argon2.argon2id,
  });
}

/** 校验密码是否与数据库中的哈希匹配 */
export async function verifyPassword(
  password: string,
  passwordHash: string,
) {
  return argon2.verify(passwordHash, password);
}
```

`hashPassword()` 用于生成密码哈希，`verifyPassword()` 用于登录时验证用户输入的密码是否匹配数据库中的哈希。

Argon2 会在哈希结果中保存算法参数和随机盐等信息。验证时不需要取出原始密码，也不需要自己生成盐后拼接字符串。注意 `verify()` 的参数顺序是先哈希、后明文密码。

如果项目已经存在密码哈希和登录验证模块，应优先复用现有实现，不要创建两套密码处理机制。若当前登录代码使用其他算法，则应保持登录与注册的算法一致。

## 四、实现用户创建 Service

Service 负责业务规则和数据库操作，不负责读取表单，也不直接操作页面状态。

打开 `server/user/service.ts`，保留已有的 `listUserPage()`，在同一个文件中增加用户创建逻辑。

```ts
// server/user/service.ts
import "server-only";

import { Prisma } from "@/app/generated/prisma/client";
import { db } from "@/lib/db";
import { hashPassword } from "@/server/auth/password";
import type { CreateUserInput } from "./schema";

export type CreateUserResult =
  | { success: true }
  | {
      success: false;
      code: "USERNAME_EXISTS" | "INVALID_INPUT" | "ERROR";
      message: string;
    };

export async function createUser(
  input: CreateUserInput,
): Promise<CreateUserResult> {
  const username = input.username.trim();

  // 预先检查用户名，提供友好的错误提示。
  const existingUser = await db.user.findUnique({
    where: { username },
    select: { id: true },
  });

  if (existingUser) {
    return {
      success: false,
      code: "USERNAME_EXISTS",
      message: "该用户名已存在",
    };
  }

  // 确认密码不参与持久化。
  const passwordHash = await hashPassword(input.password);

  try {
    await db.user.create({
      data: {
        username,
        name: input.name.trim(),
        email: input.email,
        phone: input.phone,
        passwordHash,
        status: input.status,
      },
    });

    return { success: true };
  } catch (error) {
    // 处理并发情况下两个请求同时创建同一用户名的问题。
    if (
      error instanceof Prisma.PrismaClientKnownRequestError &&
      error.code === "P2002"
    ) {
      return {
        success: false,
        code: "USERNAME_EXISTS",
        message: "该用户名已存在",
      };
    }

    throw error;
  }
}
```

上面的 Prisma 导入路径应以项目生成器的实际输出为准。如果项目已经在 `lib/db.ts` 中统一导出了 Prisma 类型，也可以使用项目现有的导入方式。不要为了这一节重新生成一套 Prisma Client。

如果项目使用的生成路径不是 `@/app/generated/prisma/client`，请将该导入改成与 `lib/db.ts` 一致的路径。

这里的处理顺序是：

1. 检查用户名是否存在。
2. 将原始密码转换为哈希。
3. 创建数据库记录。
4. 返回明确的业务结果。

为什么还要捕获 `P2002`？

因为前置查询不能解决并发问题。两个请求可能同时发现用户名不存在，然后同时尝试创建。真正保证唯一性的是数据库上的 `@unique` 约束，而 Service 负责把唯一键冲突转换为用户可以理解的提示。

`confirmPassword` 不会传入 `db.user.create()`，因此数据库只会保存必要的用户资料和 `passwordHash`。

## 五、实现 Server Action

Server Action 是客户端调用服务端逻辑的入口。

它需要负责：

- 获取当前登录用户。
- 检查当前操作者是否有创建用户的权限。
- 校验客户端提交的数据。
- 调用 Service。
- 返回适合界面展示的结果。
- 刷新用户列表。

新建 `server/user/actions.ts`：

与部门管理保持一致，项目的 Server Action 统一放在 `server/<模块>/actions.ts` 中（部门管理是 `server/dept/actions.ts`），而不是放在页面路由目录里。这样服务端逻辑与页面结构解耦，业务组件通过 `@/server/user/actions` 导入。

```ts
"use server";

import { revalidatePath } from "next/cache";
import { getCurrentSession } from "@/server/auth/session";
import { createUser } from "@/server/user/service";
import { createUserSchema } from "@/server/user/schema";

export type CreateUserActionState = {
  success: boolean;
  message: string;
  fieldErrors?: Record<string, string[] | undefined>;
};

export async function createUserAction(
  input: unknown,
): Promise<CreateUserActionState> {
  // 1. 检查登录状态。
  const session = await getCurrentSession();

  if (!session) {
    return {
      success: false,
      message: "登录状态已失效，请重新登录",
    };
  }

  // 2. 在这里接入项目实际的权限校验。
  // 例如：要求当前用户拥有 user:create 权限。
  // 不要仅凭前端隐藏按钮来控制权限。
  //
  // await requirePermission("user:create");

  // 3. 服务端重新校验输入。
  const parsed = createUserSchema.safeParse(input);

  if (!parsed.success) {
    return {
      success: false,
      message: "请检查输入内容",
      fieldErrors: parsed.error.flatten().fieldErrors,
    };
  }

  try {
    // 4. 调用 Service。
    const result = await createUser(parsed.data);

    if (!result.success) {
      return {
        success: false,
        message: result.message,
      };
    }

    // 5. 刷新用户列表。
    revalidatePath("/users");

    return {
      success: true,
      message: "用户创建成功",
    };
  } catch (error) {
    console.error("createUserAction failed", error);

    return {
      success: false,
      message: "创建用户失败，请稍后重试",
    };
  }
}
```

**重要的权限说明：** 当前项目的 `getCurrentSession()` 只能确认会话是否有效，并不能自动证明操作者拥有用户管理权限。因此，上面的 `requirePermission("user:create")` 是需要接入项目实际权限服务的扩展点，不能把注释掉的代码当作已经完成了权限控制。

如果当前项目还没有服务端权限校验函数，应先补齐权限服务，并在启用新增功能前完成接入。不要仅因为用户能够访问 Dashboard，就默认他有权创建其他账号。

另外，`revalidatePath("/users")` 的路径应与项目实际的用户管理路由一致。

## 六、实现新增用户弹窗

接下来实现界面。继续使用项目现有的 shadcn/Base UI 组件，不在业务页面里重新编写原生按钮、输入框或弹窗。

如果项目已经有 `Dialog`、`Input`、`Button`、`Label`，直接复用。如果缺少其中某些组件，再使用项目当前配置的 shadcn CLI 添加相应组件。

新建 `app/(dashboard)/users/_components/create-user-dialog.tsx`：

```tsx

import { useRouter } from "next/navigation";

import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Label } from "@/components/ui/label";
import {
  Dialog,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
} from "@/components/ui/dialog";
import {
  Select,
  SelectContent,
  SelectItem,
  SelectTrigger,
  SelectValue,
} from "@/components/ui/select";

import { createUserAction } from "@/server/user/actions";

type Props = {
  onCreated?: () => void;
};

const initialForm = {
  username: "",
  name: "",
  email: "",
  phone: "",
  password: "",
  confirmPassword: "",
  status: "ACTIVE" as "ACTIVE" | "DISABLED",
};

/** 状态下拉选项：value 用内部枚举，label 用中文，按钮上显示中文 */
const statusItems = [
  { value: "ACTIVE", label: "启用" },
  { value: "DISABLED", label: "停用" },
];

export function CreateUserDialog({ onCreated }: Props) {
  const router = useRouter();
  const [open, setOpen] = useState(false);
  const [pending, startTransition] = useTransition();

  const [form, setForm] = useState(initialForm);
  const [message, setMessage] = useState("");
  const [fieldErrors, setFieldErrors] = useState<
    Record<string, string[] | undefined>
  >({});

  function updateField(
    field: keyof typeof initialForm,
    value: string,
  ) {
    setForm((current) => ({
      ...current,
      [field]: value,
    }));

    setFieldErrors((current) => ({
      ...current,
      [field]: undefined,
    }));

    setMessage("");
  }

  function closeDialog() {
    if (pending) return;

    setOpen(false);
    setForm(initialForm);
    setMessage("");
    setFieldErrors({});
  }

  function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();
    setMessage("");
    setFieldErrors({});

    startTransition(async () => {
      const result = await createUserAction(form);

      if (!result.success) {
        setMessage(result.message);
        setFieldErrors(result.fieldErrors ?? {});
        return;
      }

      setOpen(false);
      setForm(initialForm);
      setMessage("");
      setFieldErrors({});

      router.refresh();
      onCreated?.();
    });
  }

  function errorFor(field: string) {
    return fieldErrors[field]?.[0];
  }

  return (
    <>
      <Button onClick={() => setOpen(true)}>
        新增用户
      </Button>

      {/* Base UI 弹窗用条件渲染控制开关，避免关闭动画被打断后卡死 */}
      {open && (
        <Dialog
          open
          onOpenChange={(nextOpen) => {
            if (!nextOpen) {
              closeDialog();
            }
          }}
        >
          <DialogContent className="sm:max-w-lg">
            <DialogHeader>
              <DialogTitle>新增用户</DialogTitle>
              <DialogDescription>
                填写账号信息并设置初始密码。
              </DialogDescription>
            </DialogHeader>

            <form onSubmit={handleSubmit} className="space-y-4">
              <div className="space-y-2">
                <Label htmlFor="username">用户名 *</Label>
                <Input
                  id="username"
                  autoComplete="off"
                  value={form.username}
                  onChange={(event) =>
                    updateField("username", event.target.value)
                  }
                  aria-invalid={Boolean(errorFor("username"))}
                  required
                  disabled={pending}
                />
                {errorFor("username") && (
                  <p className="text-sm text-destructive">
                    {errorFor("username")}
                  </p>
                )}
              </div>

              <div className="space-y-2">
                <Label htmlFor="name">姓名 *</Label>
                <Input
                  id="name"
                  value={form.name}
                  onChange={(event) =>
                    updateField("name", event.target.value)
                  }
                  aria-invalid={Boolean(errorFor("name"))}
                  required
                  disabled={pending}
                />
                {errorFor("name") && (
                  <p className="text-sm text-destructive">
                    {errorFor("name")}
                  </p>
                )}
              </div>

              <div className="grid gap-4 sm:grid-cols-2">
                <div className="space-y-2">
                  <Label htmlFor="email">邮箱</Label>
                  <Input
                    id="email"
                    type="email"
                    value={form.email}
                    onChange={(event) =>
                      updateField("email", event.target.value)
                    }
                    aria-invalid={Boolean(errorFor("email"))}
                    disabled={pending}
                  />
                  {errorFor("email") && (
                    <p className="text-sm text-destructive">
                      {errorFor("email")}
                    </p>
                  )}
                </div>

                <div className="space-y-2">
                  <Label htmlFor="phone">手机号</Label>
                  <Input
                    id="phone"
                    value={form.phone}
                    onChange={(event) =>
                      updateField("phone", event.target.value)
                    }
                    aria-invalid={Boolean(errorFor("phone"))}
                    disabled={pending}
                  />
                  {errorFor("phone") && (
                    <p className="text-sm text-destructive">
                      {errorFor("phone")}
                    </p>
                  )}
                </div>
              </div>

              <div className="space-y-2">
                <Label htmlFor="password">初始密码 *</Label>
                <Input
                  id="password"
                  type="password"
                  autoComplete="new-password"
                  value={form.password}
                  onChange={(event) =>
                    updateField("password", event.target.value)
                  }
                  aria-invalid={Boolean(errorFor("password"))}
                  required
                  disabled={pending}
                />
                <p className="text-xs text-muted-foreground">
                  至少 12 个字符，避免使用常见弱密码。
                </p>
                {errorFor("password") && (
                  <p className="text-sm text-destructive">
                    {errorFor("password")}
                  </p>
                )}
              </div>

              <div className="space-y-2">
                <Label htmlFor="confirmPassword">确认密码 *</Label>
                <Input
                  id="confirmPassword"
                  type="password"
                  autoComplete="new-password"
                  value={form.confirmPassword}
                  onChange={(event) =>
                    updateField("confirmPassword", event.target.value)
                  }
                  aria-invalid={Boolean(errorFor("confirmPassword"))}
                  required
                  disabled={pending}
```

这里有三处与通用示例不同的实现细节，均来自项目实际情况：

1. **弹窗用条件渲染控制开关。** 项目的 Dialog 基于 Base UI，直接切换 `open` 属性关闭弹窗时，动画被打断可能导致弹窗卡死（部门管理的删除弹窗就遇到过这个问题）。因此外层用 `{open && (<Dialog open ...>)}` 条件渲染，关闭时直接卸载组件，行为可靠。
2. **状态选择器使用项目的 `Select` 组件。** 与部门管理编辑弹窗一致，通过 `items` 传入选项，`value` 用内部枚举（`ACTIVE` / `DISABLED`），`label` 用中文（启用 / 停用），按钮上始终显示中文标签。
3. `createUserAction` 从 `@/server/user/actions` 导入，与项目把 Action 放在 `server/<模块>/actions.ts` 的约定一致。

客户端组件只负责收集输入、展示错误和管理弹窗状态。真正的输入校验、权限检查、密码哈希和数据库写入都在服务端完成。

## 八、验证新增流程

实现后不要只验证“点按钮能创建成功”，还要验证异常输入和服务端边界。

| 测试场景 | 预期结果 |
| --- | --- |
| 正常填写必填字段 | 创建成功，列表出现新用户 |
| 用户名重复 | 返回友好提示，不创建重复记录 |
| 用户名不符合规则 | 服务端拒绝 |
| 密码不足 12 个字符 | 服务端拒绝 |
| 使用已配置的弱密码 | 服务端拒绝 |
| 两次密码不一致 | 服务端拒绝 |
| 邮箱格式错误 | 服务端拒绝 |
| 绕过前端直接调用 Action | 仍然执行服务端校验和权限检查 |
| 未登录调用 Action | 返回登录状态失效 |
| 操作者没有创建用户权限 | 服务端拒绝 |
| 数据库中查看密码字段 | 只看到哈希，不出现原始密码 |
| 创建失败 | 弹窗保留输入并显示错误信息 |

最后检查数据库中 `User` 的字段，确认 `passwordHash` 不会出现在列表查询的 `select` 中。用户列表只返回展示所需的数据，不应将密码哈希传递给客户端。

## 九、本节小结

至此，用户新增形成了完整的数据写入链路：

```text
新增用户弹窗
    ↓
Server Action
    ├── 检查登录状态
    ├── 检查创建权限
    └── Zod 校验
          ↓
     User Service
    ├── 检查用户名
    ├── 生成密码哈希
    └── 写入数据库
          ↓
     刷新用户列表
```

这一节真正需要掌握的，不是如何写一个表单，而是如何把输入校验、权限控制、业务规则、密码处理和数据库写入组织成清晰的服务端流程。
