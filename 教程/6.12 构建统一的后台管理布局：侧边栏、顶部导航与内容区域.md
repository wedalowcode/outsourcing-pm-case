# 6.12 构建统一的后台管理布局：侧边栏、顶部导航与内容区域

# 一、为什么需要统一的后台布局？

前面几节，我们已经完成了部门管理的增删改查。用户可以查看部门列表、新增部门、编辑部门信息以及删除部门。

但此时还有一个问题：部门管理页面直接占据了整个浏览器窗口。随着系统功能不断增加，如果客户管理、商机管理、项目管理都采用同样的方式开发，每个页面就会像一个独立的网站，缺少统一的操作入口。

我们需要先解决一个更基础的问题：**如何把多个业务功能组织到同一个后台管理系统中？**

常见的后台管理系统一般采用下面这种布局：

```text
┌──────────────────────────────────────────────────────┐
│                  顶部导航栏                          │
├────────────┬─────────────────────────────────────────┤
│            │                                         │
│  系统名称  │            页面标题                     │
│            │                                         │
│  工作台    │            业务内容                     │
│            │                                         │
│  组织管理  │            部门管理                     │
│            │            部门树 + 部门列表             │
│  客户管理  │                                         │
│            │                                         │
│  项目管理  │                                         │
│            │                                         │
└────────────┴─────────────────────────────────────────┘
```

整个页面分为三个区域。

1. **左侧导航栏：** 展示系统的功能菜单，用户通过菜单切换不同模块。
2. **顶部导航栏：** 展示系统名称、当前页面信息以及后续可以扩展的用户入口。
3. **右侧内容区域：** 展示当前选中菜单对应的业务页面。

这三个区域的职责不同，但共同构成了一个完整的后台管理界面。

本节的目标不是重新开发部门管理，而是把现有的部门管理页面放入统一布局中，并为后续业务模块提供可以复用的页面框架。

# 二、先理解 Next.js 中的布局机制

在开始写代码之前，我们需要先理解 Next.js App Router 中的两个重要概念：`page.tsx` 和 `layout.tsx`。

## 1. page.tsx 负责页面内容

我们现在的部门管理页面位于：

```text
app/
└── dept/
    ├── page.tsx
    ├── dept-workspace.tsx
    └── ...
```

其中，`page.tsx` 负责部门管理页面的数据获取和页面入口，`dept-workspace.tsx` 负责部门树、部门列表以及相关交互。

它们属于部门管理模块本身。

如果以后增加客户管理，我们还会创建客户管理页面；增加项目管理，也会创建项目管理页面。

这些页面之间的业务逻辑不同，但它们不应该重复编写侧边栏和顶部导航。

## 2. layout.tsx 负责共享页面结构

Next.js 的 `layout.tsx` 可以为它下面的多个页面提供共享布局。

例如：

```text
layout.tsx
├── 部门管理页面
├── 客户管理页面
├── 商机管理页面
└── 项目管理页面
```

当用户从部门管理切换到其他业务页面时，共享布局可以继续存在，只需要切换右侧的页面内容。

这正是我们需要的效果。

## 3. 为什么使用路由组？

如果直接把后台导航写进 `app/layout.tsx`，那么未来的登录页、注册页等页面也可能被迫使用这套后台布局。

为了解决这个问题，我们可以使用 Next.js 的**路由组**。

路由组使用圆括号命名，例如：

```text
app/
├── layout.tsx
└── (dashboard)/
    ├── layout.tsx
    ├── dashboard/
    │   └── page.tsx
    └── dept/
        └── page.tsx
```

这里的 `(dashboard)` 是路由组名称，不会出现在最终 URL 中。

因此：

- `app/(dashboard)/dashboard/page.tsx` 对应 `/dashboard`
- `app/(dashboard)/dept/page.tsx` 对应 `/dept`

这样，我们就可以把后台管理系统的页面放在同一个路由组中，让它们共享后台布局，而不影响原有的访问地址。

# 三、调整项目目录结构

我们先把部门管理页面纳入后台路由组。

调整后的结构如下：

```text
app/
├── layout.tsx
├── globals.css
└── (dashboard)/
    ├── layout.tsx
    ├── dashboard/
    │   └── page.tsx
    └── dept/
        ├── page.tsx
        ├── dept-types.ts
        ├── dept-workspace.tsx
        └── ...
```

这里有两个需要注意的地方。

第一，原来 `app/dept` 下的部门管理文件，整体移动到 `app/(dashboard)/dept` 下，内部相对引用也需要检查。

第二，不能同时保留 `app/dept/page.tsx` 和 `app/(dashboard)/dept/page.tsx`，因为它们都映射到 `/dept`，会产生路由冲突。

调整完成后，部门管理的 URL 仍然是 `/dept`，不需要修改现有的业务地址。

# 四、创建后台共享布局

首先，在 `app/(dashboard)/layout.tsx` 中定义后台布局。

```tsx
import type { ReactNode } from "react";
import { DashboardShell } from "@/components/layout/dashboard-shell";

export default function DashboardLayout({
  children,
}: {
  children: ReactNode;
}) {
  return <DashboardShell>{children}</DashboardShell>;
}
```

这段代码做了什么？

- `children` 代表当前路由对应的页面内容。
- `DashboardShell` 负责渲染统一的后台框架。
- 部门管理页面、工作台页面等，会作为 `children` 进入这个框架。

这里没有直接在 `layout.tsx` 中写大量导航和样式，而是把具体的布局实现交给 `DashboardShell`。

这样做的好处是职责清晰：路由布局负责组织页面，布局组件负责呈现界面。

# 五、实现侧边栏和顶部导航

接下来创建布局组件：

```text
components/
└── layout/
    └── dashboard-shell.tsx
```

我们使用 Tailwind CSS 完成基础布局，并通过 Next.js 的 `Link` 实现页面跳转。

创建 `components/layout/dashboard-shell.tsx`：

```tsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";
import type { ReactNode } from "react";

const navigation = [
  {
    title: "工作台",
    href: "/dashboard",
  },
  {
    title: "部门管理",
    href: "/dept",
  },
];

export function DashboardShell({
  children,
}: {
  children: ReactNode;
}) {
  const pathname = usePathname();

  return (
    <div className="flex min-h-screen bg-slate-50 text-slate-900">
      {/* 左侧导航栏 */}
      <aside className="flex w-60 shrink-0 flex-col border-r bg-white">
        <div className="flex h-16 items-center border-b px-6">
          <span className="text-lg font-semibold">
            项目管理平台
          </span>
        </div>

        <nav className="flex-1 space-y-1 p-3">
          {navigation.map((item) => {
            const active = pathname === item.href;

            return (
              <Link
                key={item.href}
                href={item.href}
                className={[
                  "flex items-center rounded-md px-3 py-2.5",
                  "text-sm transition-colors",
                  active
                    ? "bg-slate-100 font-medium text-slate-950"
                    : "text-slate-600 hover:bg-slate-50 hover:text-slate-950",
                ].join(" ")}
              >
                {item.title}
              </Link>
            );
          })}
        </nav>

        <div className="border-t p-4 text-xs text-slate-500">
          全栈实战项目
        </div>
      </aside>

      {/* 右侧区域 */}
      <div className="flex min-w-0 flex-1 flex-col">
        {/* 顶部导航栏 */}
        <header className="flex h-16 shrink-0 items-center justify-between border-b bg-white px-6">
          <div className="text-sm text-slate-500">
            项目管理系统
          </div>

          <div className="text-sm text-slate-600">
            管理员
          </div>
        </header>

        {/* 当前页面内容 */}
        <main className="min-w-0 flex-1 p-6">
          {children}
        </main>
      </div>
    </div>
  );
}
```

这段代码是本节的核心，我们逐部分理解。

## 1. 使用 Flexbox 划分左右区域

最外层：

```tsx
<div className="flex min-h-screen bg-slate-50 text-slate-900">
```

`flex` 表示使用 Flexbox 布局，子元素默认沿水平方向排列。

因此，左侧 `aside` 和右侧内容容器会并排显示。

`min-h-screen` 则保证页面最小高度覆盖整个浏览器视口。

侧边栏使用：

```tsx
<aside className="flex w-60 shrink-0 flex-col border-r bg-white">
```

其中：

- `w-60` 设置侧边栏宽度。
- `shrink-0` 防止侧边栏在空间不足时被压缩。
- `flex-col` 让侧边栏内部的标题、菜单和底部信息垂直排列。
- `border-r` 增加右侧分隔线。

这样，侧边栏就有了稳定的宽度和独立的结构。

### 2. 让右侧内容区域自动占据剩余空间

右侧容器使用：

```tsx
<div className="flex min-w-0 flex-1 flex-col">
```

`flex-1` 表示它会占据侧边栏之外的剩余空间。

`min-w-0` 也很重要：当右侧包含较宽的表格等内容时，它允许内容区域在 Flex 布局中正确收缩，避免宽内容轻易把整个后台撑开。

内部再使用 `flex-col`，让顶部导航和页面内容上下排列。

## 3. 顶部导航与页面内容分离

顶部导航使用：

```tsx
<header className="flex h-16 shrink-0 items-center justify-between border-b bg-white px-6">
```

`h-16` 设置固定高度，`shrink-0` 防止顶部栏被压缩。

`justify-between` 让左右两侧的信息分别靠向两端。

当前我们先展示系统名称和管理员入口。后续可以再加入面包屑、用户菜单、消息通知等功能，但不必在这一节一次性实现所有内容。

## 4. 用 children 承载业务页面

```tsx
<main className="min-w-0 flex-1 p-6">
  {children}
</main>
```

这里的 `children` 就是当前路由对应的页面内容。

当访问 `/dept` 时，它接收部门管理页面；访问 `/dashboard` 时，它接收工作台页面。

**布局组件不需要知道部门管理内部如何查询数据、如何新增部门，也不需要知道部门树如何渲染。** 它只负责提供一个稳定的页面容器。

这就是共享布局与业务页面之间的职责边界。

# 六、创建工作台页面，验证菜单切换

现在导航菜单中已经包含 `/dashboard`，我们需要创建对应的页面，才能完整验证菜单跳转。

创建 `app/(dashboard)/dashboard/page.tsx`：

```tsx
export default function DashboardPage() {
  return (
    <div className="space-y-6">
      <div>
        <h1 className="text-2xl font-semibold">
          工作台
        </h1>

        <p className="mt-2 text-sm text-slate-500">
          欢迎使用项目管理平台。
        </p>
      </div>

      <section className="rounded-lg border bg-white p-6">
        <h2 className="font-medium">系统概览</h2>

        <p className="mt-2 text-sm text-slate-500">
          后续可以在这里展示项目数量、任务进度、
          待处理事项等业务数据。
        </p>
      </section>
    </div>
  );
}
```

这里先放置一个简单的工作台占位页面，不涉及新的业务查询。

现在我们有两个页面：

- `/dashboard`：工作台。
- `/dept`：部门管理。

两个页面都会自动使用 `app/(dashboard)/layout.tsx` 提供的共享布局。

如果部门管理页面原来使用了：

```tsx
<main className="p-6">
  ...
</main>
```

那么可以去掉这一层重复的页面外壳，让它只保留自己的业务内容，统一由共享布局控制外层的内容区域和留白。

注意：只去掉重复的外层布局，不要删除部门树、部门列表、弹窗以及原有的数据交互逻辑。

# 七、根据当前路由高亮菜单

侧边栏除了跳转页面，还需要告诉用户当前位于哪个模块。

前面我们已经写了：

```tsx
const pathname = usePathname();
```

它可以获取当前路由路径。

然后通过：

```tsx
const active = pathname === item.href;
```

判断当前菜单是否匹配当前页面。

如果访问 `/dept`，部门管理菜单就会使用：

```tsx
"bg-slate-100 font-medium text-slate-950"
```

如果访问 `/dashboard`，工作台菜单就会高亮。

这里使用的是精确匹配，适合当前只有两个简单页面的场景。

如果后续出现 `/dept/detail/123` 这样的嵌套页面，是否高亮部门管理菜单，就需要根据实际的路由层级调整匹配规则，避免仅靠字符串包含判断而误匹配其他路由。

# 八、运行项目并检查效果

启动开发服务器：

```bash
pnpm dev
```

打开浏览器，分别访问：

```text
http://localhost:3000/dashboard
http://localhost:3000/dept
```

重点检查以下内容：

1. 两个页面左侧都出现相同的导航栏。
2. 顶部导航保持一致，不会随着业务页面切换而重复出现。
3. 点击“部门管理”，进入原有部门管理页面。
4. 点击“工作台”，进入工作台页面。
5. 当前所在页面对应的菜单能够正确高亮。
6. 部门管理原有的查询、新增、编辑和删除功能仍然正常。
7. 右侧表格等宽内容不会轻易撑破整个后台布局。

如果项目配置了 ESLint 和生产构建检查，可以继续运行：

```bash
pnpm lint
pnpm build
```

如果调整目录后出现模块找不到的错误，优先检查文件移动后相对路径是否仍然正确，以及是否存在重复的 `/dept` 路由。

# 九、这一课建立了什么能力？

这一节看起来只是增加了一个侧边栏和顶部导航，但实际上，我们改变了整个系统组织页面的方式。

之前，部门管理页面需要自己处理完整的页面外壳；现在，页面只需要关注部门管理本身，外层布局由统一的后台框架负责。

这为后续开发带来三个直接好处。

**第一，页面结构统一。**

客户管理、商机管理、项目管理可以共享相同的导航、顶部栏和内容区域，不必每个模块重新开发一遍。

**第二，业务功能与页面框架分离。**

部门管理仍然负责自己的数据查询、业务操作和交互逻辑；后台布局负责菜单和页面结构。两者可以独立演进。

**第三，后续扩展有了明确入口。**

以后增加一个业务模块，除了实现它自己的页面，还需要将对应路由纳入后台路由组，并在导航配置中增加菜单入口。

需要注意的是，统一布局并不意味着所有页面都必须长得一样。列表页、详情页、表单页可以拥有不同的内部结构，但它们可以共享同一个后台外框。

本节完成后，我们就从“开发一个部门管理页面”迈出了下一步，开始搭建一套能够容纳多个业务模块的后台管理系统。

后续可以在这个基础上逐步扩展菜单分组、折叠侧边栏、面包屑、用户菜单和权限控制，而不必推翻当前的页面结构。
