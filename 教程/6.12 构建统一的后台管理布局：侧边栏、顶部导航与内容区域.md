# 6.12 构建统一的后台管理布局：侧边栏、顶部导航与内容区域

# 一、为什么需要统一的后台布局？

前面几节，我们已经完成了部门管理的增删改查。用户可以查看部门列表、新增部门、编辑部门信息以及删除部门。

但此时还有一个问题：部门管理页面直接占据了整个浏览器窗口。随着系统功能不断增加，如果客户管理、商机管理、项目管理都采用同样的方式开发，每个页面就会像一个独立的网站，缺少统一的操作入口。

我们需要先解决一个更基础的问题：**如何把多个业务功能组织到同一个后台管理系统中？**

常见的后台管理系统一般采用下面这种布局：

```text
┌──────────────────────────────────────────────────────┐
│                  顶部导航栏                          │
├────────────┬─────────────────────────────────────────┤
│            │                                         │
│  系统名称  │            页面标题                     │
│            │                                         │
│  工作台    │            业务内容                     │
│            │                                         │
│  组织管理  │            部门管理                     │
│            │            部门树 + 部门列表             │
│  客户管理  │                                         │
│            │                                         │
│  项目管理  │                                         │
│            │                                         │
└────────────┴─────────────────────────────────────────┘
```

整个页面分为三个区域。

1. **左侧导航栏：** 展示系统的功能菜单，用户通过菜单切换不同模块。
2. **顶部导航栏：** 展示系统名称、当前页面信息以及后续可以扩展的用户入口。
3. **右侧内容区域：** 展示当前选中菜单对应的业务页面。

这三个区域的职责不同，但共同构成了一个完整的后台管理界面。

本节的目标不是重新开发部门管理，而是把现有的部门管理页面放入统一布局中，并为后续业务模块提供可以复用的页面框架。

# 二、先理解 Next.js 中的布局机制

在开始写代码之前，我们需要先理解 Next.js App Router 中的两个重要概念：`page.tsx` 和 `layout.tsx`。

## 1. page.tsx 负责页面内容

本章开始前，部门管理页面位于 `app/dept`；纳入后台路由组之后，它会被移动到 `app/(dashboard)/dept`。重构完成后的目录结构是：

```text
app/
└── (dashboard)/
    └── dept/
        ├── page.tsx
        ├── loading.tsx
        ├── error.tsx
        ├── _components/
        │   └── workspace.tsx
        └── ...
```

其中，`page.tsx` 负责部门管理页面的数据获取和页面入口，`loading.tsx` 与 `error.tsx` 分别处理加载态和错误态，`_components/workspace.tsx` 负责部门树、部门列表以及相关交互。

它们属于部门管理模块本身。

如果以后增加客户管理，我们还会创建客户管理页面；增加项目管理，也会创建项目管理页面。

这些页面之间的业务逻辑不同，但它们不应该重复编写侧边栏和顶部导航。

## 2. layout.tsx 负责共享页面结构

Next.js 的 `layout.tsx` 可以为它下面的多个页面提供共享布局。

例如：

```text
layout.tsx
├── 部门管理页面
├── 客户管理页面
├── 商机管理页面
└── 项目管理页面
```

当用户从部门管理切换到其他业务页面时，共享布局可以继续存在，只需要切换右侧的页面内容。

这正是我们需要的效果。

## 3. 为什么使用路由组？

如果直接把后台导航写进 `app/layout.tsx`，那么未来的登录页、注册页等页面也可能被迫使用这套后台布局。

为了解决这个问题，我们可以使用 Next.js 的**路由组**。

路由组使用圆括号命名，例如：

```text
app/
├── layout.tsx
└── (dashboard)/
    ├── layout.tsx
    ├── dashboard/
    │   └── page.tsx
    └── dept/
        └── page.tsx
```

这里的 `(dashboard)` 是路由组名称，不会出现在最终 URL 中。

因此：

- `app/(dashboard)/dashboard/page.tsx` 对应 `/dashboard`
- `app/(dashboard)/dept/page.tsx` 对应 `/dept`

这样，我们就可以把后台管理系统的页面放在同一个路由组中，让它们共享后台布局，而不影响原有的访问地址。

# 三、调整项目目录结构

我们先把部门管理页面纳入后台路由组。

调整后的结构如下：

```text
app/
├── layout.tsx
├── globals.css
└── (dashboard)/
    ├── layout.tsx
    ├── dashboard/
    │   └── page.tsx
    └── dept/
        ├── page.tsx
        ├── loading.tsx
        ├── error.tsx
        ├── _components/
        │   ├── workspace.tsx
        │   ├── dept-table.tsx
        │   ├── tree-node-item.tsx
        │   ├── dept-edit-dialog.tsx
        │   └── delete-dialog.tsx
        └── ...
```

此外，页面标题会抽成公共组件 `components/common/page-header.tsx`，供页面入口、加载态和错误态共用，具体在第六节说明。

这里有两个需要注意的地方。

第二，不能同时保留 `app/dept/page.tsx` 和 `app/(dashboard)/dept/page.tsx`，因为它们都映射到 `/dept`，会产生路由冲突。

调整完成后，部门管理的 URL 仍然是 `/dept`，不需要修改现有的业务地址。

# 四、创建后台共享布局

首先，在 `app/(dashboard)/layout.tsx` 中定义后台布局。

```tsx
import type { ReactNode } from "react";
import { redirect } from "next/navigation";

import { AppLayout } from "@/components/layout/app-layout";
import { getCurrentSession } from "@/server/auth/session";

export default async function DashboardLayout({
  children,
}: {
  children: ReactNode;
}) {
  const session = await getCurrentSession();

  if (!session) {
    redirect("/login");
  }

  return (
    <AppLayout userName={session.user.name}>
      {children}
    </AppLayout>
  );
}
```

这段代码做了什么？

- 先调用 `getCurrentSession()` 取当前登录态，未登录直接 `redirect("/login")`，这是**路由守卫**。
- 守卫通过后，从 `session.user.name` 取出用户名，传给 `<AppLayout>`。
- `children` 代表当前路由对应的页面内容。部门管理页面、工作台页面等，会作为 `children` 进入这个框架。

这里没有直接在 `layout.tsx` 中写导航和样式，它只做三件事：**取 session → 守卫 → 把 children 和用户名交给 AppLayout**。具体的界面呈现交给 `components/layout/` 下的组件们。

这样做的好处是职责清晰：路由布局负责鉴权和数据准备，布局组件负责呈现界面。

# 五、实现侧边栏和顶部导航

接下来创建布局组件。我们把原来一个大组件拆成四个小文件，各司其职：

```text
components/
└── layout/
    ├── app-layout.tsx       ← 总容器，摆放 Sidebar / Header / main
    ├── sidebar.tsx          ← 侧边栏外框（logo + SidebarMenu + 底部）
    ├── sidebar-menu.tsx     ← 菜单项数组 + 高亮逻辑（客户端组件）
    ├── header.tsx           ← 顶部导航栏
    └── user-actions.tsx     ← 用户信息 + 退出登录（客户端组件）
```

每个文件只做一件事，后续加新菜单或改顶部栏，直接改对应文件即可。我们用 Tailwind CSS 完成基础布局，通过 Next.js 的 `Link` 实现页面跳转。

### 1. 总容器 `app-layout.tsx`

负责把侧边栏、顶部栏和主内容区摆到正确的位置：

```tsx
import type { ReactNode } from "react";
import { Header } from "./header";
import { Sidebar } from "./sidebar";

export function AppLayout({
  children,
  userName,
}: {
  children: ReactNode;
  userName: string;
}) {
  return (
    <div className="flex min-h-screen bg-muted/40">
      <Sidebar />
      <div className="flex min-w-0 flex-1 flex-col">
        <Header userName={userName} />
        <main className="min-w-0 flex-1 p-6">{children}</main>
      </div>
    </div>
  );
}
```

外层 `flex` 让 `Sidebar` 和右侧内容并排显示；右侧容器再用 `flex-col` 让 `Header` 和 `main` 上下排列。`AppLayout` 本身不写导航细节，也不处理路由，它只负责摆放。

### 2. 侧边栏外框 `sidebar.tsx`

负责侧边栏的骨架：顶部 logo、中间菜单、底部版权信息：

```tsx
import { SidebarMenu } from "./sidebar-menu";

export function Sidebar() {
  return (
    <aside className="flex w-60 shrink-0 flex-col border-r bg-background">
      <div className="flex h-16 items-center border-b px-6 text-lg font-semibold">
        项目管理平台
      </div>
      <SidebarMenu />
      <div className="border-t p-4 text-xs text-muted-foreground">
        全栈实战项目
      </div>
    </aside>
  );
}
```

- `w-60` 设置侧边栏宽度，`shrink-0` 防止被压缩。
- `border-r` 增加右侧分隔线。
- 中间直接复用 `SidebarMenu`，不在这里写菜单项。

### 3. 菜单逻辑 `sidebar-menu.tsx`

这是一个客户端组件（需要 `usePathname`），定义菜单项数组、处理高亮：

```tsx
"use client";

import Link from "next/link";
import { usePathname } from "next/navigation";
import { cn } from "cn";

const NAV_ITEMS = [
  { label: "工作台", href: "/dashboard" },
  { label: "部门管理", href: "/dept" },
  { label: "用户管理", href: "/users" },
  { label: "角色管理", href: "/roles" },
];

export function SidebarMenu() {
  const pathname = usePathname();

  return (
    <nav className="flex-1 space-y-1 p-3">
      {NAV_ITEMS.map((item) => {
        const isActive =
          pathname === item.href ||
          pathname.startsWith(`${item.href}/`);

        return (
          <Link
            key={item.href}
            href={item.href}
            className={cn(
              "flex items-center rounded-md px-3 py-2.5 text-sm transition-colors",
              "text-muted-foreground hover:bg-accent hover:text-accent-foreground",
              isActive && "bg-accent font-medium text-accent-foreground"
            )}
          >
            {item.label}
          </Link>
        );
      })}
    </nav>
  );
}
```

几个要点：

- 菜单项常量叫 `NAV_ITEMS`（大写常量风格），每项用 `item.label`（不是 `title`）。
- `isActive` 用**精确匹配 + 前缀匹配**：访问 `/dept/detail/123` 时部门管理菜单仍然高亮，避免写嵌套路由后丢失高亮。
- 样式使用 shadcn 主题 token（`bg-accent`、`text-muted-foreground`、`text-accent-foreground`），不写死 `slate-*`，后续切换深色模式或换色板时自动生效。
- 用 `cn()` 工具函数拼接条件样式，比手写字符串数组更整洁。

### 4. 顶部栏 `header.tsx` 与用户操作 `user-actions.tsx`

`Header` 负责顶部栏外框，`UserActions` 处理用户名显示和退出登录按钮。两者配合完成顶部导航栏：

`components/layout/header.tsx`：

```tsx
import { UserActions } from "./user-actions";

export function Header({ userName }: { userName: string }) {
  return (
    <header className="flex h-16 shrink-0 items-center justify-between border-b bg-background px-6">
      <span className="text-sm text-muted-foreground">项目管理系统</span>
      <UserActions userName={userName} />
    </header>
  );
}
```

`Header` 只接一个 `userName`，因为它自己不处理鉴权，鉴权在 `layout.tsx` 已经完成。

`components/layout/user-actions.tsx`：

```tsx
"use client";

import { useState } from "react";
import { useRouter } from "next/navigation";
import { Button } from "@/components/ui/button";
import { logoutAction } from "@/server/auth/actions";

export function UserActions({ userName }: { userName: string }) {
  const router = useRouter();
  const [isLoggingOut, setIsLoggingOut] = useState(false);
  const [errorMessage, setErrorMessage] = useState("");

  async function handleLogout() {
    if (isLoggingOut) return;

    setIsLoggingOut(true);
    setErrorMessage("");

    try {
      const result = await logoutAction();

      if (result.ok) {
        router.replace("/login");
        return;
      }

      setErrorMessage("退出登录失败，请重试");
    } catch {
      setErrorMessage("退出登录失败，请稍后重试");
    }

    setIsLoggingOut(false);
  }

  return (
    <div className="flex items-center gap-3">
      {errorMessage && (
        <span className="text-sm text-destructive" role="alert">
          {errorMessage}
        </span>
      )}

      <span className="text-sm text-muted-foreground">{userName}</span>

      <Button
        variant="outline"
        size="sm"
        disabled={isLoggingOut}
        onClick={handleLogout}
      >
        {isLoggingOut ? "退出中..." : "退出登录"}
      </Button>
    </div>
  );
}
```

退出登录的实现逻辑：

1. 点击按钮，`isLoggingOut` 置为 `true`，按钮禁用、文案变成"退出中..."。
2. 调用 `logoutAction()`（Server Action），成功后 `router.replace("/login")` 直接跳登录页，**不用** `router.refresh()`，也不用 `finally` 恢复按钮——页面马上会跳走。
3. 失败时（业务错误或网络异常），设置 `errorMessage`，走到最后统一 `setIsLoggingOut(false)` 恢复按钮可点状态。
4. 错误提示显示在用户名**左边**，出现时按钮位置不会跳动。

---

把四个文件合起来，整体效果和原来一个大组件完全一样，但职责分散到了四个小文件里。后续新增菜单改 `sidebar-menu.tsx`，改顶部系统名称改 `header.tsx`，加退出登录逻辑改 `user-actions.tsx`，互不影响。

下面逐部分理解各段的样式设计逻辑。

## 1. 使用 Flexbox 划分左右区域

最外层：

```tsx
<div className="flex min-h-screen bg-muted/40">
```

`flex` 表示使用 Flexbox 布局，子元素默认沿水平方向排列。

因此，左侧 `Sidebar` 和右侧内容容器会并排显示。

`min-h-screen` 则保证页面最小高度覆盖整个浏览器视口。

侧边栏使用：

```tsx
<aside className="flex w-60 shrink-0 flex-col border-r bg-background">
```

其中：

- `w-60` 设置侧边栏宽度。
- `shrink-0` 防止侧边栏在空间不足时被压缩。
- `flex-col` 让侧边栏内部的标题、菜单和底部信息垂直排列。
- `border-r` 增加右侧分隔线。

这样，侧边栏就有了稳定的宽度和独立的结构。

### 2. 让右侧内容区域自动占据剩余空间

右侧容器使用：

```tsx
<div className="flex min-w-0 flex-1 flex-col">
```

`flex-1` 表示它会占据侧边栏之外的剩余空间。

`min-w-0` 也很重要：当右侧包含较宽的表格等内容时，它允许内容区域在 Flex 布局中正确收缩，避免宽内容轻易把整个后台撑开。

内部再使用 `flex-col`，让顶部导航和页面内容上下排列。

## 3. 顶部导航与页面内容分离

顶部导航使用：

```tsx
<header className="flex h-16 shrink-0 items-center justify-between border-b bg-background px-6">
```

`h-16` 设置固定高度，`shrink-0` 防止顶部栏被压缩。

`justify-between` 让左右两侧的信息分别靠向两端。

当前我们先展示系统名称和管理员入口。后续可以再加入面包屑、用户菜单、消息通知等功能，但不必在这一节一次性实现所有内容。

## 4. 用 children 承载业务页面

```tsx
<main className="min-w-0 flex-1 p-6">
  {children}
</main>
```

这里的 `children` 就是当前路由对应的页面内容。

当访问 `/dept` 时，它接收部门管理页面；访问 `/dashboard` 时，它接收工作台页面。

**布局组件不需要知道部门管理内部如何查询数据、如何新增部门，也不需要知道部门树如何渲染。** 它只负责提供一个稳定的页面容器。

这就是共享布局与业务页面之间的职责边界。

# 六、抽取公共 PageHeader，统一页面、加载态与错误态

后台布局解决的是整页框架，页面内部还需要有稳定的标题区域。本节把页面标题抽成公共组件，并完成部门页入口、加载态和错误态的整理。

## 1. 公共组件 page-header.tsx

创建 `components/common/page-header.tsx`：

```tsx
import type { ReactNode } from "react";

/** 页面标题：page / loading / error 共用，保证三者布局一致 */
export function PageHeader({
  title,
  children,
}: {
  title: string;
  children?: ReactNode;
}) {
  return (
    <div className="mb-4 flex items-center justify-between gap-3">
      <h1 className="text-xl font-semibold">{title}</h1>
      {children}
    </div>
  );
}
```

组件只有两个参数：

- `title`：页面标题。
- `children`：标题右侧的扩展位置，后续可以放“新增”“导出”等操作按钮。

`page.tsx`、`loading.tsx`、`error.tsx` 都从这里渲染标题，因此标题的位置、字号和下方间距完全一致。加载中和出错时，标题不会跳动，页面结构也保持稳定。

## 2. 页面入口 page.tsx

`app/(dashboard)/dept/page.tsx` 只负责读取查询参数、取数和组装数据，具体交互仍然交给 `_components/workspace.tsx`：

```tsx
import { PageHeader } from "@/components/common/page-header";
import { buildTree } from "@/server/dept/tree";
import { toRow } from "@/server/dept/mappers";
import { DeptQuerySchema } from "@/server/dept/schema";
import { listDeptPage, listDepts } from "@/server/dept/service";
import { DeptWorkspace } from "./_components/workspace";

export default async function DeptPage({
  searchParams,
}: {
  searchParams: Promise<Record<string, string | string[] | undefined>>;
}) {
  // 这一版 Next.js 里 searchParams 是异步的，必须先 await；
  // 同时用 Zod 兜底：重复参数会变成数组，直接调字符串方法会抛错
  const params = DeptQuerySchema.parse(await searchParams);

  // 两个查询互不依赖，可以并行
  const [allRows, data] = await Promise.all([
    listDepts(), // 全量数据：给组织树和“上级部门名称”用
    listDeptPage({
      keyword: params.keyword,
      parentId: params.parent,
      page: params.page,
      pageSize: 10,
    }),
  ]);

  // 上级部门名称：用已经取到的全量数据做映射，不用再查一次库
  const nameById = new Map(allRows.map((row) => [row.id, row.name]));

  return (
    <>
      <PageHeader title="部门管理" />

      <DeptWorkspace
        tree={buildTree(allRows)}
        pageData={{
          rows: data.rows.map((row) => toRow(row, nameById)),
          total: data.total,
          page: data.page,
          pageSize: data.pageSize,
        }}
        keyword={params.keyword}
        selectedId={params.parent ?? null}
      />
    </>
  );
}
```

这段代码有四个要点。

第一，`searchParams` 是异步的。这一版 Next.js 传入的是 `Promise`，所以必须先 `await searchParams`，不能直接按同步对象读取。

第二，查询参数要经过 Zod 兜底。URL 里的重复参数会变成数组，例如 `?keyword=a&keyword=b`，直接对数组调用字符串方法就会抛错。`DeptQuerySchema` 用 `.catch()` 把非法值降级成安全默认值：

```ts
export const DeptQuerySchema = z.object({
  keyword: z.string().trim().catch(""),
  parent: z.string().min(1).optional().catch(undefined),
  page: z.coerce.number().int().min(1).catch(1),
});
```

第三，两个查询互不依赖，使用 `Promise.all` 并行执行：`listDepts()` 取全量数据，供组织树和“上级部门名称”使用；`listDeptPage(...)` 按关键字、上级部门、页码取当前页数据。

第四，组装数据时复用已有工具：`buildTree`（来自 `@/server/dept/tree`）把全量数据组装成组织树；`toRow`（来自 `@/server/dept/mappers`）把数据库记录转换成表格行，并用 `nameById` 补上上级部门名称。页面最后把 `tree`、`pageData`、`keyword`、`selectedId` 传给 `DeptWorkspace`。

页面交互组件统一放在 `_components/workspace.tsx`，文件名不再带模块前缀——目录 `dept/` 已经说明了模块归属。

## 3. loading.tsx：与页面同栅格的骨架屏

## 4. error.tsx：保留 retry，只展示错误编号

创建 `app/(dashboard)/dept/error.tsx`：

```tsx
"use client"; // 错误边界必须是客户端组件

import { PageHeader } from "@/components/common/page-header";
import { Button } from "@/components/ui/button";

/**
 * 这一版 Next 的错误边界参数是 `retry`（`reset` 只清空错误状态、不重新取数）。
 * 详见 node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/error.md。
 */
export default function DeptError({
  error,
  retry,
}: {
  error: Error & { digest?: string };
  retry: () => void;
}) {
  return (
    <>
      <PageHeader title="部门数据加载失败" />

      {/* 生产环境的 error.message 会被脱敏，这里只展示可检索的错误编号 */}
      <p className="text-sm text-muted-foreground">
        请稍后重试
        {error.digest ? `（错误编号：${error.digest}）` : ""}
      </p>

      <Button
        type="button"
        variant="outline"
        className="mt-4"
        onClick={() => retry()}
      >
        重试
      </Button>
    </>
  );
}
```

错误边界必须是客户端组件，所以文件顶部有 `"use client"`。这里有两个容易写错的地方。

一是参数用 `retry`，不是 `reset`。这一版 Next.js 的错误边界提供 `retry`，调用它会重新执行出错的数据请求；`reset` 只清空错误状态，不会重新取数。

二是不要展示 `error.message`。生产环境里的 message 会被脱敏，用户看到的往往没有意义；这里只展示可检索的 `digest`（错误编号），方便对照服务端日志。按钮使用 `variant="outline"`，和页面里的其他次要操作保持一致。

# 八、根据当前路由高亮菜单

侧边栏除了跳转页面，还需要告诉用户当前位于哪个模块。

前面我们已经写了：

```tsx
const pathname = usePathname();
```

它可以获取当前路由路径。

然后通过：

```tsx
const isActive =
  pathname === item.href ||
  pathname.startsWith(`${item.href}/`);
```

判断当前菜单是否匹配当前页面。精确匹配处理 `/dept` 这种纯路由，前缀匹配处理 `/dept/detail/123` 这种嵌套路由——访问子页面时上级菜单仍然保持高亮。

如果访问 `/dept`，部门管理菜单就会使用：

```tsx
"bg-accent font-medium text-accent-foreground"
```

如果访问 `/dashboard`，工作台菜单就会高亮。

这里用的是 shadcn 主题 token（`bg-accent` / `text-accent-foreground`），不是写死的 `slate-*` 颜色值，后续切换深色模式或换色板时自动生效。

# 十、这一课建立了什么能力？

这一节看起来只是增加了一个侧边栏和顶部导航，但实际上，我们改变了整个系统组织页面的方式。

之前，部门管理页面需要自己处理完整的页面外壳；现在，页面只需要关注部门管理本身，外层布局由统一的后台框架负责。

这为后续开发带来三个直接好处。

**第一，页面结构统一。**

客户管理、商机管理、项目管理可以共享相同的导航、顶部栏和内容区域，不必每个模块重新开发一遍。

**第二，业务功能与页面框架分离。**

部门管理仍然负责自己的数据查询、业务操作和交互逻辑；后台布局负责菜单和页面结构。两者可以独立演进。

**第三，后续扩展有了明确入口。**

以后增加一个业务模块，除了实现它自己的页面，还需要将对应路由纳入后台路由组，并在导航配置中增加菜单入口。

需要注意的是，统一布局并不意味着所有页面都必须长得一样。列表页、详情页、表单页可以拥有不同的内部结构，但它们可以共享同一个后台外框。

本节完成后，我们就从“开发一个部门管理页面”迈出了下一步，开始搭建一套能够容纳多个业务模块的后台管理系统。

后续可以在这个基础上逐步扩展菜单分组、折叠侧边栏、面包屑、用户菜单和权限控制，而不必推翻当前的页面结构。
