# 6.10 使用 shadcn/ui 实现部门新增与编辑功能

# 一、前言

在前面的章节中，我们已经完成了部门管理的后端开发。

目前，部门模块已经具备以下能力：

- **Schema**：定义输入数据的结构和校验规则。
- **Service**：实现部门新增、修改、删除等业务逻辑。
- **Action**：为前端提供调用后端业务能力的入口。
- **单元测试**：验证 Action 的调用行为，确保后端入口能够按照预期执行。

后端已经准备就绪，接下来要解决的问题是：**如何让用户通过页面操作，真正使用这些功能？**

从用户的角度来看，部门管理应该是这样的：

1. 进入部门管理页面，查看部门列表。
2. 点击“新增部门”，打开弹窗。
3. 填写部门信息，点击保存。
4. 前端调用新增 Action，将数据提交给后端。
5. 后端经过业务校验，将数据保存到数据库。
6. 保存成功后，关闭弹窗；Action 内部的 `revalidatePath` 会让部门列表同步更新。

编辑部门也遵循同样的流程，只是打开弹窗时需要先加载当前部门的数据，并在保存时调用更新 Action。

为了完成这套交互，我们使用 shadcn/ui 提供的 `Button`、`Input`、`Select`、`Textarea` 和 `Dialog` 等组件。

但本篇的重点并不只是使用这些 UI 组件，而是把它们与已经完成的后端能力连接起来，形成一个完整的业务操作闭环。

# 二、先明确前后端的职责

开始编写代码之前，我们先明确各部分的职责。

| 模块 | 负责的工作 |
|---|---|
| 部门列表页面 | 展示部门数据、触发新增和编辑操作 |
| 部门编辑弹窗 | 展示表单、维护输入状态、进行基础校验，并维护提交状态与错误信息 |
| Server Action | 接收前端提交的数据，调用后端业务逻辑 |
| Service | 校验业务规则，执行部门新增或修改 |
| Prisma | 将业务操作转换为数据库操作 |
| PostgreSQL | 持久化部门数据 |

整体调用链路如下：

```text
部门列表
   │
   ├── 点击新增
   │      │
   │      ▼
   │   打开空白表单
   │
   └── 点击编辑
          │
          ▼
       打开已有数据的表单
          │
          ▼
       用户填写并保存
          │
          ▼
       父组件调用 Action
          │
          ▼
       Service 执行业务校验
          │
          ▼
       Prisma 写入数据库
          │
          ▼
       返回执行结果
          │
          ├── 失败：保留弹窗，显示错误
          │
          └── 成功：关闭弹窗，列表随 revalidatePath 更新
```

这里有一个重要的设计：**弹窗负责收集数据、维护提交状态和执行基础校验，父组件只负责选择调用哪个 Action，并在成功后关闭弹窗。**

这样，表单组件不需要知道数据库如何操作，也不需要承担列表刷新的职责。将来客户、商机和项目模块也可以采用类似的组织方式。

# 三、安装 shadcn/ui 组件

如果项目尚未初始化 shadcn/ui，需要先完成初始化。本案例执行的是：

```bash
pnpm dlx shadcn@latest init -y -d
pnpm dlx shadcn@latest add button input textarea select dialog card badge label table
```

初始化完成后，`components.json` 的 `style` 为 `base-nova`，底层实现是 **Base UI**（而不是 Radix UI）。这一点很重要：接下来写 `Select` 和 `Dialog` 时，必须按照 Base UI 的 API 来写。

本篇涉及的组件如下：

| 组件 | 用途 |
|---|---|
| `Button` | 新增、编辑、取消、保存 |
| `Input` | 部门名称、部门编码、排序 |
| `Select` | 上级部门、部门状态 |
| `Textarea` | 部门描述 |
| `Dialog` | 承载新增和编辑表单 |
| `Card` | 组织架构区域、表单区域的容器 |
| `Badge` | 部门启用 / 停用等状态标签 |
| `Label` | 表单字段标签（`FormField` 内部使用） |
| `Table` | 部门列表 |

组件生成后，检查 `components/ui/` 目录，确认这些文件已经存在：

```text
components/ui/
├── button.tsx
├── input.tsx
├── textarea.tsx
├── select.tsx
├── dialog.tsx
├── card.tsx
├── badge.tsx
├── label.tsx
└── table.tsx
```

初始化同时还会做两件事：

**第一，生成 `lib/utils.ts`。**内容只是把 shadcn 新版提供的 `cn` 包再导出一次：

```typescript
export { cn } from "cn"
```

`cn` 用来合并 Tailwind 类名，生成出来的组件文件都从它引入。也就是说，组件里会出现 `import { cn } from "cn"` 这种写法，它指向的是初始化时新装的 `cn` 依赖，不是项目里的相对路径。

**第二，改写 `app/globals.css`。**补充 shadcn 组件需要的主题变量（`--primary`、`--border`、`--input`、`--muted` 等）。原有的 Tailwind 工具类和页面样式不受影响。

初始化还会一并把这些依赖写进 `package.json`：`cn`、`@base-ui/react`、`class-variance-authority`、`tw-animate-css`、`lucide-react`（以及 CLI 自身的 `shadcn`）。这些都由 CLI 自动完成，不需要手工处理。

需要注意，shadcn/ui 可以选择不同的底层实现，例如 Radix UI 或 Base UI。后续使用 `Select` 和 `Dialog` 时，应以当前项目生成的组件 API 为准，避免把不同实现的写法混用。

## 4. 补充三个公共组件

除了 shadcn 生成的组件，本次重构还把表单中重复出现的结构和状态标签抽成了公共组件。`FormField` 和 `OptionSelect` 放在 `components/common/`，`Badge` 属于 shadcn 组件，放在 `components/ui/`。

`components/common/form-field.tsx`：

```tsx
import type { ReactNode } from "react";
import { Label } from "@/components/ui/label";

/** 标签 + 控件的固定结构，保证各表单项间距一致 */
export function FormField({
  label,
  htmlFor,
  children,
}: {
  label: string;
  htmlFor?: string;
  children: ReactNode;
}) {
  return (
    <div className="space-y-1.5">
      <Label htmlFor={htmlFor} className="text-xs text-muted-foreground">
        {label}
      </Label>
      {children}
    </div>
  );
}
```

`FormField` 统一了“标签 + 控件”的排版：调用方只需要传 `label` 和控件本身，不用每个字段都重复写一遍 `label` 和间距类名。

`components/common/option-select.tsx`：

```tsx
"use client";

import {
  Select,
  SelectContent,
  SelectItem,
  SelectTrigger,
  SelectValue,
} from "@/components/ui/select";

type Option = {
  value: string;
  label: string;
};

/** 统一的下拉选择封装，省去重复的 trigger / content 结构 */
export function OptionSelect({
  items,
  value,
  onChange,
}: {
  items: Option[];
  value: string;
  onChange: (value: string) => void;
}) {
  return (
    <Select
      items={items}
      value={value}
      onValueChange={(next) => onChange(String(next))}
    >
      <SelectTrigger className="w-full">
        <SelectValue />
      </SelectTrigger>

      <SelectContent>
        {items.map((item) => (
          <SelectItem key={item.value} value={item.value}>
            {item.label}
          </SelectItem>
        ))}
      </SelectContent>
    </Select>
  );
}
```

`OptionSelect` 把 Base UI 的 `Select`、`SelectTrigger`、`SelectContent` 等结构封装在一起，调用方只需要准备 `items`、当前值和 `onChange`。这里把 Base UI 回调里的值统一转成字符串，避免不同字段还要各自处理类型。

`components/ui/badge.tsx`：

```tsx
import * as React from "react";
import { cva, type VariantProps } from "class-variance-authority";
import { cn } from "cn";

const badgeVariants = cva(
  "inline-flex items-center justify-center rounded-full border px-2 py-0.5 text-xs font-medium whitespace-nowrap transition-colors",
  {
    variants: {
      variant: {
        default: "border-transparent bg-primary text-primary-foreground",
        secondary: "border-transparent bg-secondary text-secondary-foreground",
        destructive:
          "border-transparent bg-destructive/10 text-destructive dark:bg-destructive/20",
        outline: "border-border text-foreground",
      },
    },
    defaultVariants: {
      variant: "default",
    },
  }
);

function Badge({
  className,
  variant,
  ...props
}: React.ComponentProps<"span"> & VariantProps<typeof badgeVariants>) {
  return (
    <span
      data-slot="badge"
      className={cn(badgeVariants({ variant }), className)}
      {...props}
    />
  );
}

export { Badge, badgeVariants };
```

`Badge` 用 `cva` 定义了 `default`、`secondary`、`destructive`、`outline` 几种样式变体，表格里的启用 / 停用状态就用它来展示。

# 四、创建部门表单弹窗

先创建文件：

```text
app/dept/_components/dept-edit-dialog.tsx
```

这个组件需要支持新增和编辑两种模式。

新增模式使用默认值，编辑模式使用选中部门的数据。为了让两个操作共用一套表单，我们定义统一的表单数据类型。

下面先给出这个文件的完整代码，然后再逐步解释其中的关键设计。

## 1. 完整代码

```tsx
"use client";

import { useState } from "react";
import { Button } from "@/components/ui/button";
import {
  Dialog,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
} from "@/components/ui/dialog";
import { Input } from "@/components/ui/input";
import { Textarea } from "@/components/ui/textarea";
import { FormField } from "@/components/common/form-field";
import { OptionSelect } from "@/components/common/option-select";
import type {
  DeptInput,
  DeptStatus,
  Row,
  TreeNode,
} from "@/server/dept/types";

/** 上级部门下拉里代表“无（顶级部门）”的哨兵值 */
const ROOT_OPTION = "__ROOT__";

/** 新增、编辑共用的表单数据类型 */
export type DeptForm = {
  name: string;
  code: string;
  parentId: string | null;
  sort: string;
  status: DeptStatus;
  description: string;
};

/** 新增模式下的默认表单值 */
export function emptyForm(parentId: string | null): DeptForm {
  return {
    name: "",
    code: "",
    parentId,
    sort: "",
    status: 1,
    description: "",
  };
}

/** 表格行 → 表单值（编辑弹窗回显） */
export function toForm(row: Row): DeptForm {
  return {
    name: row.name,
    code: row.code,
    parentId: row.parentId,
    sort: String(row.sort),
    status: row.status === 1 ? 1 : 0,
    description: row.description ?? "",
  };
}

/** 表单值 → Action 入参 */
export function toDeptInput(form: DeptForm): DeptInput {
  return {
    name: form.name.trim(),
    parentId: form.parentId,
    sort: form.sort.trim() ? Number(form.sort) : undefined,
    status: form.status,
    description: form.description.trim(),
  };
}

type FlatOption = {
  id: string;
  label: string;
};

/** 把部门树拍平成下拉选项，缩进体现层级，并跳过被排除的部门 */
function flattenTree(
  nodes: TreeNode[],
  excludeIds: string[],
  depth = 0
): FlatOption[] {
  const options: FlatOption[] = [];

  for (const node of nodes) {
    if (excludeIds.includes(node.id)) continue;

    options.push({
      id: node.id,
      label: `${"　".repeat(depth)}${node.name}`,
    });

    options.push(
      ...flattenTree(node.children, excludeIds, depth + 1)
    );
  }

  return options;
}

export function DeptEditDialog({
  mode,
  initial,
  tree,
  excludeIds,
  onClose,
  onSubmit,
}: {
  mode: "create" | "edit";
  initial: DeptForm;
  tree: TreeNode[];
  excludeIds: string[];
  onClose: () => void;
  /** 返回错误文案表示失败，返回 undefined 表示成功（由父组件卸载弹窗） */
  onSubmit: (form: DeptForm) => Promise<string | undefined>;
}) {
  const [form, setForm] = useState<DeptForm>(initial);
  const [submitting, setSubmitting] = useState(false);
  const [error, setError] = useState("");

  const parentOptions = flattenTree(tree, excludeIds);

  const parentItems = [
    { value: ROOT_OPTION, label: "无（顶级部门）" },
    ...parentOptions.map((option) => ({
      value: option.id,
      label: option.label,
    })),
  ];

  const statusItems = [
    { value: "1", label: "启用" },
    { value: "0", label: "停用" },
  ];

  function setField<K extends keyof DeptForm>(
    key: K,
    value: DeptForm[K]
  ) {
    setForm((prev) => ({ ...prev, [key]: value }));
  }

  async function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();
    if (submitting) return;

    // 客户端只做最基本的校验：必填、排序是整数。
    // 名称重复、上级是否合法等业务规则由服务端判断。
    if (!form.name.trim()) {
      setError("请填写部门名称");
      return;
    }

    if (form.sort.trim() && !Number.isInteger(Number(form.sort))) {
      setError("排序必须是整数");
      return;
    }

    setSubmitting(true);
    setError("");

    const message = await onSubmit(form).catch(
      () => "保存失败，请稍后重试"
    );

    setSubmitting(false);

    if (message) setError(message);
  }

  return (
    <Dialog
      open
      onOpenChange={(open) => {
        // 提交中不允许通过 Esc 或点击遮罩关闭，避免中途打断请求
        if (!open && !submitting) onClose();
      }}
    >
      <DialogContent className="sm:max-w-md">
        <DialogHeader>
          <DialogTitle>
            {mode === "create" ? "新增部门" : "编辑部门"}
          </DialogTitle>
          <DialogDescription>
            部门编码由系统自动生成，不需要手工填写。
          </DialogDescription>
        </DialogHeader>

        <form onSubmit={handleSubmit} className="space-y-3">
          <FormField label="部门名称" htmlFor="dept-name">
            <Input
              id="dept-name"
              value={form.name}
              placeholder="例如：研发部"
              disabled={submitting}
              onChange={(event) => setField("name", event.target.value)}
            />
          </FormField>

          <FormField label="部门编码" htmlFor="dept-code">
            <Input
              id="dept-code"
              value={form.code}
              placeholder="保存后自动生成"
              readOnly
              className="bg-muted/50 font-mono"
            />
          </FormField>

          <FormField label="上级部门">
            <OptionSelect
              items={parentItems}
              value={form.parentId ?? ROOT_OPTION}
              onChange={(value) =>
                setField(
                  "parentId",
                  value === ROOT_OPTION ? null : value
                )
              }
            />
          </FormField>

          <div className="grid grid-cols-2 gap-3">
            <FormField label="排序" htmlFor="dept-sort">
              <Input
                id="dept-sort"
                value={form.sort}
                placeholder="留空则自动排到末尾"
                inputMode="numeric"
                disabled={submitting}
                onChange={(event) => setField("sort", event.target.value)}
              />
            </FormField>

            <FormField label="状态">
              <OptionSelect
                items={statusItems}
                value={String(form.status)}
                onChange={(value) =>
                  setField("status", value === "1" ? 1 : 0)
                }
              />
            </FormField>
          </div>

          <FormField label="部门描述" htmlFor="dept-description">
            <Textarea
              id="dept-description"
              value={form.description}
              placeholder="选填，最多 500 字"
              rows={3}
              disabled={submitting}
              onChange={(event) =>
                setField("description", event.target.value)
              }
            />
          </FormField>

          {error ? (
            <p className="text-sm text-destructive">{error}</p>
          ) : null}

          <DialogFooter>
            <Button
              type="button"
              variant="outline"
              disabled={submitting}
              onClick={onClose}
            >
              取消
            </Button>
            <Button type="submit" disabled={submitting}>
              {submitting ? "保存中…" : "保存"}
            </Button>
          </DialogFooter>
        </form>
      </DialogContent>
    </Dialog>
  );
}
```

## 2. 定义表单类型和默认值

```tsx
export type DeptForm = {
  name: string;
  code: string;
  parentId: string | null;
  sort: string;
  status: DeptStatus;
  description: string;
};

export function emptyForm(
  parentId: string | null
): DeptForm {
  return {
    name: "",
    code: "",
    parentId,
    sort: "",
    status: 1,
    description: "",
  };
}
```

这里有两个需要注意的地方。

第一，`code` 是后端生成的部门编码，前端只负责展示，不允许用户修改。

第二，`sort` 在表单中使用字符串。输入框接收到的值本身是字符串，提交时再转换为数字。

除了新增时的默认值，编辑回显和提交转换也集中在同一个文件里：

```tsx
/** 表格行 → 表单值（编辑弹窗回显） */
export function toForm(row: Row): DeptForm {
  return {
    name: row.name,
    code: row.code,
    parentId: row.parentId,

    description: row.description ?? "",
  };
}

/** 表单值 → Action 入参 */

```

这样一来，父组件既不用手写一遍字段映射，也不会出现“回显”和“提交”两处转换规则不一致的问题。

## 3. 定义弹窗的输入参数

弹窗需要接收以下参数：

```tsx
type DeptEditDialogProps = {
  mode: "create" | "edit";
  initial: DeptForm;
  tree: TreeNode[];
  excludeIds: string[];
  onClose: () => void;
  /** 返回错误文案表示失败，返回 undefined 表示成功（由父组件卸载弹窗） */
  onSubmit: (form: DeptForm) => Promise<string | undefined>;
};
```

其中：

- `mode` 用来区分新增和编辑。
- `initial` 用来初始化表单。
- `tree` 用来展示可选的上级部门。
- `excludeIds` 用来排除当前部门及其下级部门，避免在界面上选择非法的上级部门。
- `onClose` 负责关闭弹窗。
- `onSubmit` 将表单数据交给父组件处理，并用返回值表达结果：返回错误文案表示失败，返回 `undefined` 表示成功。

注意，props 里已经不再有 `error` 和 `submitting`。这两个状态由弹窗内部维护，父组件只负责调用 Action、在成功时卸载弹窗。

`TreeNode` 应直接使用项目中已经定义的部门树类型，不需要重新创建一套类型。

## 4. 使用 shadcn/ui 实现表单

弹窗里每个字段都用 `FormField` 包一层，下拉框统一用 `OptionSelect`，外层则是一个 `<form onSubmit>`。这样点击“保存”和直接按回车都会走同一个提交函数：

```tsx
async function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
  event.preventDefault();
  if (submitting) return;

  // 客户端只做最基本的校验：必填、排序是整数。
  // 名称重复、上级是否合法等业务规则由服务端判断。
  if (!form.name.trim()) {
    setError("请填写部门名称");
    return;
  }

  if (form.sort.trim() && !Number.isInteger(Number(form.sort))) {
    setError("排序必须是整数");
    return;
  }

  setSubmitting(true);
  setError("");

  const message = await onSubmit(form).catch(
    () => "保存失败，请稍后重试"
  );

  setSubmitting(false);

  if (message) setError(message);
}
```

这段代码体现了表单组件的核心职责：先完成必要的客户端校验，再通过 `onSubmit` 将数据交给父组件，并根据返回值决定是否显示错误。

三个细节值得注意：

**第一，`submitting` 和 `error` 都由弹窗自己维护。** 提交前把 `submitting` 置为 `true`，失败后把父组件返回的文案写进 `error`，成功后父组件直接卸载弹窗，弹窗不需要自己关闭。

**第二，提交期间禁止关闭弹窗。** `Dialog` 的 `onOpenChange` 只在 `!open && !submitting` 时才调用 `onClose()`，因此 Esc 和点击遮罩在提交中都不会生效。

**第三，提交期间禁用输入。** 名称、排序、描述以及底部两个按钮都带 `disabled={submitting}`。取消按钮显式写成 `type="button"`，避免它触发 `<form>` 的提交；保存按钮则是 `type="submit"`。

这里不直接调用 Action，是为了将表单交互与业务提交分离。表单只需要知道用户点击保存后应该提交数据，不需要关心新增和编辑分别调用哪个后端入口。

弹窗内部还需要处理上级部门选择、状态选择、部门描述、关闭按钮和保存中状态。完成后，用户就可以通过统一的界面录入部门数据。

# 五、在部门列表页面管理弹窗状态

接下来打开部门管理页面对应的组件。本案例中它就是部门页面的客户端入口：

```text
app/dept/_components/workspace.tsx
```

它负责弹窗状态管理，也是整个前端唯一调用 Action 的地方。下面先给出完整代码，再逐步解释。

## 1. 完整代码

```tsx
"use client";

import { usePathname, useRouter } from "next/navigation";
import { useState, useTransition } from "react";
import { cn } from "cn";
import { Button } from "@/components/ui/button";
import {
  Card,
  CardContent,
  CardHeader,
  CardTitle,
} from "@/components/ui/card";
import { Pagination } from "./pagination";
import { SearchBar } from "./search-bar";
import {
  createDeptAction,
  updateDeptAction,
} from "@/server/dept/actions";
import { getExcludedDeptIds } from "@/server/dept/tree";
import type {
  PageData,
  TreeNode,
} from "@/server/dept/types";
import {
  DeptEditDialog,
  emptyForm,
  toDeptInput,
  toForm,
  type DeptForm,
} from "./dept-edit-dialog";
import { DeptTable } from "./dept-table";
import { TreeNodeItem } from "./tree-node-item";

/** 弹窗的三种状态：关闭 / 新增 / 编辑 */
type DialogState =
  | { mode: "create"; initial: DeptForm }
  | { mode: "edit"; initial: DeptForm; deptId: string }
  | null;

export function DeptWorkspace({
  tree,
  pageData,
  keyword,
  selectedId,
}: {
  tree: TreeNode[];
  pageData: PageData;
  keyword: string;
  selectedId: string | null;
}) {
  const router = useRouter();
  const pathname = usePathname();
  // isPending：跳转期间为 true，用来给表格一个“加载中”的视觉反馈
  const [isPending, startTransition] = useTransition();

  const [dialog, setDialog] = useState<DialogState>(null);

  /**
   * 统一的跳转入口：当前条件 + 本次改动 → 新的查询串
   * - keyword / parent：不传表示保持不变；keyword 传 ""、parent 传 null 表示清除
   * - page：不传就回到第 1 页。换搜索词、换部门都应该从头看；
   *         只有翻页时才显式传入目标页码
   */
  function go(next: { keyword?: string; parent?: string | null; page?: number }) {
    const kw = next.keyword ?? keyword;
    const pid = next.parent === undefined ? selectedId : next.parent;
    const p = next.page ?? 1;

    const sp = new URLSearchParams();
    if (kw) sp.set("keyword", kw);
    if (pid) sp.set("parent", pid);
    if (p > 1) sp.set("page", String(p));

    startTransition(() => {
      router.push(sp.size ? `${pathname}?${sp}` : pathname);
    });
  }

  /** 提交表单：返回错误文案，成功时关闭弹窗并返回 undefined */
  async function save(form: DeptForm): Promise<string | undefined> {
    if (!dialog) return;

    const payload = toDeptInput(form);

    // Action 把业务失败放在返回值里，不能只依赖 catch
    const result =
      dialog.mode === "create"
        ? await createDeptAction(payload)
        : await updateDeptAction(dialog.deptId, payload);

    if (!result.ok) return result.message;

    // Action 内部已 revalidatePath("/dept")，当前页面会随之更新
    setDialog(null);
  }

  return (
    <div className="grid grid-cols-1 gap-4 lg:grid-cols-4">
      {/* 左：组织树 */}
      <Card>
        <CardHeader>
          <CardTitle>组织架构</CardTitle>
        </CardHeader>
        <CardContent className="max-h-[70vh] space-y-0.5 overflow-y-auto">
          {tree.map((node) => (
            <TreeNodeItem
              key={node.id}
              node={node}
              depth={0}
              selectedId={selectedId}
              // 再点一次已选中的节点 = 取消选择
              onSelect={(id) => go({ parent: id === selectedId ? null : id })}
            />
          ))}
        </CardContent>
      </Card>

      {/* 右：搜索 + 表格 + 分页 */}
      <div className={cn("space-y-3 lg:col-span-3", isPending && "opacity-60")}>
        <div className="flex items-start justify-between gap-3">
          {/* key={keyword}：URL 里的关键字变了（比如点浏览器后退），输入框随之重建 */}
          <SearchBar
            key={keyword}
            defaultValue={keyword}
            onSearch={(kw) => go({ keyword: kw })}
          />
          <Button
            onClick={() =>
              setDialog({ mode: "create", initial: emptyForm(selectedId) })
            }
          >
            新增部门
          </Button>
        </div>

        <DeptTable
          rows={pageData.rows}
          emptyText={
            selectedId ? "该部门下暂无子部门" : "没有符合条件的部门"
          }
          onEdit={(row) =>
            setDialog({
              mode: "edit",
              deptId: row.id,
              initial: toForm(row),
            })
          }
        />

        <Pagination
          page={pageData.page}
          total={pageData.total}
          pageSize={pageData.pageSize}
          onChange={(page) => go({ page })}
        />
      </div>

      {dialog && (
        <DeptEditDialog
          // key：新增 / 编辑不同部门时重建表单，避免上一次的状态残留
          key={dialog.mode === "create" ? "create" : dialog.deptId}
          mode={dialog.mode}
          initial={dialog.initial}
          tree={tree}
          excludeIds={
            dialog.mode === "edit"
              ? getExcludedDeptIds(tree, dialog.deptId)
              : []
          }
          onClose={() => setDialog(null)}
          onSubmit={save}
        />
      )}
    </div>
  );
}
```

真实文件里的 `DeptTable` 还带一个 `onDelete`，删除功能留到 6.11 再接入，这里只保留 `rows`、`emptyText`、`onEdit` 三个属性。

`SearchBar` 和 `Pagination` 此时仍然位于 `app/dept/_components/`，所以按同目录的相对路径引入；它们在第 8.1 章才会移到 `components/common`。

## 2. 弹窗状态

父组件需要知道当前处于什么操作模式，以及用户正在操作哪个部门。

```tsx
type DialogState =
  | { mode: "create"; initial: DeptForm }
  | { mode: "edit"; initial: DeptForm; deptId: string }
  | null;
```

这个状态表示三种情况：

- `null`：没有打开弹窗。
- `create`：正在新增部门。
- `edit`：正在编辑已有部门。

新增时，设置默认值：

```tsx
setDialog({
  mode: "create",
  initial: emptyForm(selectedId),
});
```

如果用户在某个部门下新增子部门，可以通过 `selectedId` 把该部门的 ID 传给 `emptyForm`，让上级部门默认选中该部门。

编辑时，只需要把列表行交给 `toForm`：

```tsx
setDialog({
  mode: "edit",
  deptId: row.id,
  initial: toForm(row),
});
```

这里的 `row` 就是表格行数据 `Row`。`toForm` 会把 `row.status` 从普通数字收敛成 `DeptStatus`，把可能为 `null` 的 `row.description` 转成空字符串。因为回显逻辑都集中在 `toForm` 里，父组件不需要再逐字段拼一遍。也因为要回填部门描述，`Row` 类型本身需要包含 `description` 字段（这一点见本篇第八节「需要补齐的配套改动」）。

新增和编辑都通过同一个弹窗完成，区别只在于初始数据和提交时调用的 Action。

# 六、实现 Action 调用逻辑

这是本篇最关键的部分。

前面已经完成了 Action、Service 和单元测试，因此这里不需要重新编写后端业务逻辑，而是将前端提交的数据传入现有 Action。

首先，在父组件中导入项目已经实现的 Action：

```tsx
import {
  createDeptAction,
  updateDeptAction,
} from "@/server/dept/actions";
```

这两个函数的真实签名来自上一篇的实现：

```typescript
export async function createDeptAction(input: unknown)

export async function updateDeptAction(id: string, input: unknown)

export async function deleteDeptAction(id: unknown)
```

这里有两个必须注意的地方。

**第一，入参类型是 `unknown`，不是 `DeptInput`。**因为进入 Action 的数据还没经过校验，不能直接当成合法输入使用。Action 内部会先执行 `DeptInputSchema.safeParse()`，解析通过之后才把结果当作 `DeptInput` 交给 Service。

**第二，Action 用返回值表达失败，而不是抛异常。**成功返回 `{ ok: true }`，业务失败返回 `{ ok: false, message: "具体原因" }`。所以前端必须判断 `result.ok`，不能只依赖 `try/catch`。

## 1. 提交状态由弹窗内部维护

父组件不再维护提交状态和错误文案，这两个状态下沉到了弹窗内部：

```tsx
const [submitting, setSubmitting] = useState(false);
const [error, setError] = useState("");
```

`submitting` 表示当前是否正在提交，既防止重复提交，也用来禁用输入和拦截关闭。

`error` 保存客户端校验或 Action 返回的错误文案。

父组件只保留弹窗状态和 `save` 函数：成功时卸载弹窗，失败时把错误文案原样交给弹窗显示。

## 2. 编写统一的保存函数

新增和编辑的表单结构相同，所以共用一个 `save` 函数，根据 `mode` 决定调用哪个 Action。真正落地的实现如下：

```tsx
async function save(form: DeptForm): Promise<string | undefined> {
  if (!dialog) return;

  const payload = toDeptInput(form);

  // Action 把业务失败放在返回值里，不能只依赖 catch
  const result =
    dialog.mode === "create"
      ? await createDeptAction(payload)
      : await updateDeptAction(dialog.deptId, payload);

  if (!result.ok) return result.message;

  // Action 内部已 revalidatePath("/dept")，当前页面会随之更新
  setDialog(null);
}
```

`save` 的返回值就是弹窗要展示的错误：`result.ok` 为 `false` 时返回 `result.message`，弹窗把它写进 `error`；成功时返回 `undefined`，并在这里卸载弹窗。

和上一篇的 Action 对照，这段代码有三个容易写错的地方。

**其一，`updateDeptAction` 的第一个参数是 `id`，第二个才是表单数据。**它不是 `updateDeptAction({ id, ...payload })` 这种单对象写法，而是 `updateDeptAction(id, payload)`。

**其二，失败判断用 `result.ok`，错误文案取 `result.message`。**不是 `result.success` / `result.error`。

**其三，`payload` 由 `toDeptInput` 统一生成，字段要符合后端 Schema 的约定：**

- `sort` 留空时传 `undefined`，让 Service 自己算“同级最大值 + 10”；传 `0` 是合法的，会被保留。
- `parentId` 传 `null` 表示顶级部门，`""` 会被 Schema 的 `.min(1)` 拒绝。
- `status` 是数字 `0 | 1`，不是字符串。
- `description` 允许传空字符串，Service 会把它落成 `null`。

这里不需要再手动刷新页面。`createDeptAction` / `updateDeptAction` 内部已经执行了 `revalidatePath("/dept")`，Action 返回后当前页面的数据会重新获取，列表随之更新。实测保存成功后列表会自动刷新，无需前端额外处理；如果将来某个页面不在 `revalidatePath` 覆盖的路径内，再考虑手动刷新。

## 3. 为什么成功和失败要分开处理？

用户点击保存后，可能出现两种结果。

**保存成功：**

- 关闭弹窗。
- 列表由 Action 内的 `revalidatePath` 自动更新。
- 让用户看到最新的数据。

**保存失败：**

- 保留弹窗。
- 保留用户已经输入的数据。
- 显示后端返回的错误信息。
- 允许用户修改后重新提交。

如果无论成功失败都关闭弹窗，用户在遇到部门名称重复、上级部门不合法等错误时，就可能丢失已经输入的数据。

因此，只有确认 Action 执行成功后，才应该关闭弹窗。

还有一点需要区分：`try/catch` 负责处理调用过程中抛出的异常；如果 Action 将业务失败包装在返回值中，则需要检查返回结果并显示对应错误，不能只依赖 `catch`。


# 八、需要补齐的配套改动

弹窗写完后，还有几处上下游需要一起补齐，否则页面跑不起来、或者功能会缺一块。以下都是本案例实际落地时补上的。

## 1. 恢复 `DEPT_STATUS` 常量

表格里用 `DEPT_STATUS.ENABLED` 判断状态显示，但经过上一篇的类型重构后，`server/dept/types.ts` 只保留了 `DeptStatus` 类型，常量被删掉了。需要把它加回来：

```typescript
/** 部门状态常量：0 停用，1 启用（与 schema.ts 的 DeptStatusSchema 对应） */
export const DEPT_STATUS = {
  DISABLED: 0,
  ENABLED: 1,
} as const;
```

## 2. 给 `Row` 补上 `description`

编辑弹窗要回填部门描述，但表格行类型 `Row` 原先没有这个字段。需要在两个文件里同步补上。

`server/dept/types.ts`：

```typescript
export type Row = {
  id: string;
  name: string;
  code: string;
  parentId: string | null;
  parentName: string | null; // 上级部门名称：表格要显示的是名字，不是 id
  sort: number;
  status: number;
  description: string | null; // 编辑弹窗要回填这个字段
};
```

`server/dept/types.ts` 里的 `DeptRecord`，以及 `server/dept/mappers.ts` 里的 `toRow`：

```typescript
// types.ts：建树所需的最小记录形状
export type DeptRecord = Pick<
  TreeNode,
  "id" | "name" | "code" | "parentId" | "status"
>;

// mappers.ts：表格映射还需要 sort 和 description
import type { DeptRecord, Row } from "./types";

type DeptDetail = DeptRecord & {
  sort: number;
  description: string | null;
};

/** 数据库记录 → 表格行：补上“上级部门名称” */
export function toRow(row: DeptDetail, nameById: Map<string, string>): Row {
  return {
    id: row.id,
    name: row.name,
    code: row.code,
    parentId: row.parentId,
    parentName: row.parentId ? (nameById.get(row.parentId) ?? null) : null,
    sort: row.sort,
    status: row.status,
    description: row.description,
  };
}
```

数据来源不用改。`listDeptPage` 返回的本来就是完整的部门记录，已经带了 `description`，只是 mapper 之前没有把它映射出来。

## 3. 新增 `getExcludedDeptIds`

这个纯函数放在 `server/dept/tree.ts`。它不碰数据库，只处理内存中的部门树，所以客户端组件可以直接引用：

```typescript
/**
 * 收集某个部门及其全部下级的 id。
 *
 * 编辑部门时用来排除非法的上级选项：不能把自己或自己的下级选为上级。
 */
export function getExcludedDeptIds(
  tree: TreeNode[],
  id: string
): string[] {
  function find(nodes: TreeNode[]): TreeNode | null {
    for (const node of nodes) {
      if (node.id === id) return node;

      const hit = find(node.children);
      if (hit) return hit;
    }

    return null;
  }

  function collect(node: TreeNode): string[] {
    return [node.id, ...node.children.flatMap(collect)];
  }

  const target = find(tree);

  return target ? collect(target) : [];
}
```

搜索栏要和新增按钮排在同一行，它自带的下边距会破坏这一行的对齐，所以把 `mb-3` 从组件内部移到父容器：

```diff
-    <div className="mb-3 flex gap-2">
+    <div className="flex gap-2">
```

需要说明一点：Next.js 16 已经移除了 `next lint` 命令，所以 `pnpm lint` 实际执行的是 ESLint 自身。本案例的构建结果中，`/dept` 被识别为动态路由（`ƒ`），这正是我们在前面几篇里配置 `force-dynamic` 想要的效果。

通过后，再进入页面验证完整业务流程。

| 测试场景 | 预期结果 |
|---|---|
| 打开部门管理页面 | 正常展示部门列表 |
| 点击新增部门 | 打开空白弹窗 |
| 不填写部门名称就保存 | 前端提示必填错误 |
| 填写合法数据并保存 | 调用新增 Action，保存成功后关闭弹窗 |
| 新增成功 | 部门列表自动更新，显示新增部门 |
| 点击已有部门的编辑按钮 | 弹窗显示当前部门数据 |
| 修改部门信息并保存 | 调用更新 Action，关闭弹窗后列表自动更新 |
| 提交违反业务规则的数据 | 后端拒绝保存，弹窗保留并展示错误 |
| 保存中按钮禁用、Esc/遮罩无法关闭 | 提交期间不能重复提交，也不能中断请求 |

还需要特别验证两件事。

第一，前端传给 Action 的 `payload` 是否符合已有 Schema 的要求。例如，`sort` 是否允许省略，`description` 是否允许为空，都应该与后端约定保持一致。

第二，后端是否已经在成功后执行了 `revalidatePath` 等缓存失效操作。本案例的 Action 已经调用 `revalidatePath("/dept")`，实测保存成功后列表会自动更新，前端无需再手动刷新。

# 十、小结

本篇完成的是部门管理从后端到前端的连接。

我们使用 shadcn/ui 构建表单控件和弹窗，在部门列表页面管理新增、编辑状态，并通过统一的提交函数调用已经完成的 Action。

整个流程形成了一个完整的闭环：

- 用户在列表中发起新增或编辑操作。
- 弹窗负责收集和校验输入数据。
- 父组件根据操作模式调用对应的 Action。
- Service 执行业务规则并完成数据库操作。
- 前端根据执行结果决定关闭弹窗还是显示错误。
- 保存成功后由 Action 内的 `revalidatePath` 触发列表更新。

这套结构的价值在于职责清晰：UI 组件负责界面，表单负责输入，Action 负责调用入口，Service 负责业务规则。

后续开发客户、商机和项目模块时，我们可以沿用这个模式。再往后，可以将重复的表单布局、字段校验和控件渲染抽取成统一组件，逐步构建自己的业务表单组件库。
