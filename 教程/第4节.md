# 一、 需求梳理及方案设计
## 1. 需求拆解与知识识别

表面上看，产品经理只说了一句话：“做个部门管理页面，左侧显示部门树。” 但在动手前，我们需要把这句简单的话拆解为 4 个底层的技术问题：

* **数据模型与存储**：数据库里保存的是平铺的部门记录（带 `parentId`），如何设计“自关联”结构？
* **数据结构转换**：如何把数据库返回的扁平数组，转换成前端需要的层级树形结构（`children: TreeNode[]`）？
* **组件架构与递归**：前端树状节点的结构是无限层级嵌套的，如何编写递归组件并处理逻辑？
* **状态管理与数据流**：节点的“展开/收起”（局部状态）与“当前选中部门”（全局/容器状态）应该分别由谁管理？

## 2. 状态职责划分与链路推导

为了让代码职责清晰、避免状态混乱，我们将状态与数据流明确分工：

* **数据提供者（Server Component / API）**：负责从 PostgreSQL 读取原始数据，并通过 `buildTree()` 组装成树形 JSON。
* **页面容器（`DeptWorkspace`）**：负责管理**页面级状态**（如 `selectedId` 当前选中的部门 ID）。
* **树节点组件（`TreeNodeItem`）**：负责管理**节点级状态**（如 `expanded` 展开/收起）以及自身的递归渲染。

**系统整体运行链路：**

$$\text{PostgreSQL (扁平数据)} \longrightarrow \text{Prisma / Service (buildTree 转换为树)} \longrightarrow \text{DeptPage (服务端获取)} \longrightarrow \text{DeptWorkspace (选中状态)} \longrightarrow \text{TreeNodeItem (展开状态/递归渲染)} \longrightarrow \text{浏览器视图}$$

## 3. 从方案推导文件结构

根据上面的职责划分，我们不需要盲目新建文件，而是顺理成章地推导出每个文件具体的职责：

```text
server/
  dept/
    types.ts              # 1. 共享数据类型定义 (TreeNode)
    service.ts            # 2. 数据库查询（只负责读库，标记 server-only）
    tree.ts               # 3. 扁平数组转树算法（buildTree 纯函数）

app/
  dept/
    page.tsx              # 4. 服务端页面入口 (负责 Fetch 数据)
    loading.tsx           # 5. 加载态兜底
    error.tsx             # 6. 错误兜底（必须是客户端组件）
    dept-workspace.tsx    # 7. 客户端容器 (管理 selectedId 选中状态)
    _components/
      tree-node-item.tsx  # 8. 递归节点组件 (管理 expanded 展开状态 + UI 渲染)

```

这里有两个容易踩坑的细节，先说明白：

**一是类型的归属。** `TreeNode` 被 `server/` 和 `app/` 两边同时用到。如果把它放在 `app/dept/dept-types.ts`，就等于服务层反过来依赖页面层——**依赖方向反了**。正确做法是放到中立位置 `server/dept/types.ts`，两边都从那里引用：页面依赖服务层，而不是服务层依赖页面。

**二是目录命名。** 组件目录用 `_components` 而不是 `components`。在 App Router 里，只有 `page.tsx` / `route.ts` 才会变成公开路由，所以 `components` 本身也不会变成路由；但加上下划线前缀是官方约定的**私有文件夹**写法，能更明确地告诉后来的人：这里只是内部组件，不参与路由。

有了这个清晰的推导图谱，接下来的实现步骤就非常明确了。我们将按照“底层数据 $\rightarrow$ 服务层 $\rightarrow$ 共享类型 $\rightarrow$ 组装算法 $\rightarrow$ 页面入口 $\rightarrow$ 兜底组件 $\rightarrow$ 交互容器 $\rightarrow$ 递归组件”的时间顺序，一步步把方案变成代码。

## 第二步：编写后端服务（只负责查库）

创建文件：`server/dept/service.ts`

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/74935397708a41fe9c57874c91e31ef7.png)


这个文件的职责只有一个：**`listDepts`，从数据库全量读取扁平部门列表**。至于把扁平数组拼成树，那是下一步的事——查库和算法分开，各管一件事。

```typescript
import "server-only";

import { db } from "@/lib/db";

// 从数据库全量读取扁平部门列表
export async function listDepts() {
  return db.dept.findMany({
    orderBy: [{ sort: "asc" }, { name: "asc" }],
  });
}

```

第一行的 `import "server-only";` 需要先装一个包：

```bash
pnpm add server-only
```

它是官方推荐的**服务端专属标记**。加上这一行之后，只要有人不小心在客户端组件里引入这个文件，构建阶段就会直接报错，而不是等到运行时才发现数据库连接串被打进了浏览器。凡是直接访问数据库的文件，都建议这样标记。

## 第三步：定义共享数据类型

创建文件：`server/dept/types.ts`

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/6d2dd430a0f849e2b76b36fbde43fe52.png)


我们需要定义前后端统一下发与接收的数据结构。`children` 属性包含自身类型的数组，这就是典型的**递归数据类型**。

```typescript
export type TreeNode = {
  id: string;
  name: string;
  code: string;
  parentId: string | null;
  status: number;
  children: TreeNode[]; // 递归嵌套结构
};

```

注意这个文件放在 `server/dept/` 下，而不是 `app/dept/` 下。原因在第一节已经说过：它同时被服务层的 `tree.ts` 和页面层的组件引用，放在中立位置，两边都依赖它，才不会出现服务层反向依赖页面层。

## 第四步：编写扁平数组转树的算法

创建文件：`server/dept/tree.ts`

`buildTree` 是一个**纯函数**：不碰数据库、不依赖请求上下文，输入扁平数组、输出树。拆出来的好处是它可以被单独测试，也方便以后在别处复用。

```typescript
import type { listDepts } from "./service";
import type { TreeNode } from "./types";

// 算法核心：将扁平数组转换为 Tree 结构
export function buildTree(
  rows: Awaited<ReturnType<typeof listDepts>>,
  parentId: string | null = null
): TreeNode[] {
  return rows
    .filter((row) => row.parentId === parentId) // 步骤 A：找出当前层级的节点
    .map((row) => ({
      id: row.id,
      name: row.name,
      code: row.code,
      parentId: row.parentId,
      status: row.status,
      // 步骤 B：递归寻找当前节点的所有子节点
      children: buildTree(rows, row.id),
    }));
}

```

🔍 **深度剖析：`buildTree` 算法的执行链路**

假设数据库拿到的是平铺数据：`[总公司(id:A, p:null), 技术部(id:B, p:A), 前端组(id:C, p:B)]`：

1. **首次调用** `buildTree(rows, null)`：
* `filter` 匹配到 `parentId === null` 的节点：**总公司 A**。


2. **生成子树**：
* 为总公司生成 `children`，触发递归调用 `buildTree(rows, "A")`。


3. **第二层递归**：
* `filter` 匹配到 `parentId === "A"` 的节点：**技术部 B**。
* 继续为技术部递归调用 `buildTree(rows, "B")`。


4. **第三层递归**：
* `filter` 匹配到 `parentId === "B"` 的节点：**前端组 C**。
* 继续调用 `buildTree(rows, "C")`，由于没有 `parentId === "C"` 的数据，`filter` 返回空数组 `[]`，递归在此**终止**并逐层向上返回。



> **复杂度提示**：每层递归都会对整个数组做一次 `filter`，整体复杂度是 $O(n^2)$。部门几百条以内完全没问题；如果以后数据量大幅增长，可以先把所有行按 `parentId` 分组成 `Map`，再一次性遍历组装。

## 第五步：实现服务端页面入口

创建文件：`app/dept/page.tsx`

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/3088828cfba34179bcb0b8ecb134105c.png)


在 Next.js App Router 中，默认不写 `"use client"` 的文件均为**服务端组件（Server Component）**。页面在服务端直接调用数据库和算法，获取组装好的 `tree` 数据，然后向下传递给客户端组件。

```typescript
import { listDepts } from "@/server/dept/service";
import { buildTree } from "@/server/dept/tree";
import { DeptWorkspace } from "./dept-workspace";

// 每次请求都重新查库，避免构建时被静态预渲染成固定快照
export const dynamic = "force-dynamic";

export default async function DeptPage() {
  // 从数据库读取扁平数据，再组装成树
  const rows = await listDepts();
  const tree = buildTree(rows);

  return (
    <main className="p-6">
      <h1 className="mb-4 text-xl font-semibold text-gray-800">
        部门管理
      </h1>

      {/* 将准备好的树形数据打入 Workspace 交互容器 */}
      <DeptWorkspace tree={tree} />
    </main>
  );
}

```

这里多了一行 `export const dynamic = "force-dynamic";`，值得单独说明。

开发模式下，改完数据刷新页面就能看到最新结果，所以很容易误以为这个页面天然就是“实时”的。但生产构建（`pnpm build`）时，Next.js 会尽量把不需要请求信息的页面**静态预渲染**：如果页面里没有用到 `cookies()`、`headers()` 这类请求时 API，它就会在构建那一刻查一次库，把结果固化成静态页面。之后数据库再改，线上也不会变。

部门管理页显然需要每次请求都读到最新数据，所以显式声明 `force-dynamic`。它的含义是：**这个路由在每次请求时都重新渲染**，而不是在构建时生成一次。

> 提示：这个项目的 `next.config.ts` 没有开启 Cache Components，所以走的是上面这套（上一代）缓存模型，`force-dynamic` 就是标准做法。不同大版本的默认行为可能有差异，建议用 `pnpm build && pnpm start` 实测一次确认。

## 第六步：补上加载态与错误兜底

前面几步只覆盖了“成功路径”。如果查库很慢，用户会盯着白屏；如果数据库连不上，整页会直接崩掉。App Router 为这两种情况各约定了一个文件名，加起来的成本很低。

创建文件：`app/dept/loading.tsx`

这个文件会在该路由段的数据还没准备好时自动显示：

```typescript
export default function DeptLoading() {
  return (
    <main className="p-6">
      <h1 className="mb-4 text-xl font-semibold text-gray-800">
        部门管理
      </h1>

      <div className="w-64 rounded-md border border-gray-200 bg-white p-3 text-sm text-gray-400 shadow-sm">
        正在加载部门数据…
      </div>
    </main>
  );
}

```

创建文件：`app/dept/error.tsx`

这个文件会在该路由段渲染出错时显示兜底界面。注意：**错误边界必须是客户端组件**，所以第一行要写 `"use client"`。

```typescript
"use client"; // 错误边界必须是客户端组件

export default function DeptError({
  error,
  retry,
}: {
  error: Error & { digest?: string };
  retry: () => void;
}) {
  return (
    <main className="p-6">
      <h1 className="text-xl font-semibold text-gray-800">
        部门数据加载失败
      </h1>

      <p className="mt-2 text-sm text-gray-500">{error.message}</p>

      <button
        type="button"
        className="mt-4 rounded border border-gray-300 px-3 py-1 text-sm hover:bg-gray-50"
        onClick={() => retry()}
      >
        重试
      </button>
    </main>
  );
}

```

这里用的是 `retry`，不是 `reset`。在本课程使用的 Next.js 16 中，`retry` 是稳定且推荐的写法：它会**重新拉取数据并重新渲染**这个路由段，正好对应“重新查一次库”的诉求；而 `reset` 只清空错误状态、不重新取数，这种场景一般用不到。

## 第七步：实现页面客户端容器

创建文件：`app/dept/dept-workspace.tsx`

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/100a665657af4be4adbb59a6ae4da752.png)


`DeptWorkspace` 负责管理**页面级交互状态**。它不需要知道每个树节点内部是如何渲染和展开的，只需要统一记录当前用户高亮选中了哪个部门（`selectedId`）。

```typescript
"use client";

import { useState } from "react";
import type { TreeNode } from "@/server/dept/types";
import { TreeNodeItem } from "./_components/tree-node-item";

export function DeptWorkspace({ tree }: { tree: TreeNode[] }) {
  // 页面级状态：管理当前选中的部门 ID
  const [selectedId, setSelectedId] = useState<string | null>(null);

  return (
    <div className="w-64 rounded-md border border-gray-200 bg-white p-3 shadow-sm">
      <div className="mb-2 text-sm font-medium text-gray-700">
        组织架构
      </div>

      <div className="max-h-[70vh] space-y-0.5 overflow-y-auto">
        {tree.map((node) => (
          <TreeNodeItem
            key={node.id}
            node={node}
            depth={0}
            selectedId={selectedId}
            onSelect={setSelectedId}
          />
        ))}
      </div>
    </div>
  );
}

```

## 第八步：实现递归树节点组件

创建文件：`app/dept/_components/tree-node-item.tsx`

![在这里插入图片描述](https://i-blog.csdnimg.cn/direct/7063c1f6624a42afb0c11f2fe5cfe26b.png)


这是 UI 渲染的核心逻辑。利用 **React 递归组件** 特性：只要当前节点拥有子节点（`children.length > 0`），并且用户处于展开状态（`expanded === true`），组件就会**调用自身**来渲染子节点，同时将深度 `depth + 1`，通过动态内边距实现树形视觉缩进。

```typescript
"use client";

import { useState } from "react";
import type { TreeNode } from "@/server/dept/types";

type TreeNodeItemProps = {
  node: TreeNode;
  depth: number;
  selectedId: string | null;
  onSelect: (id: string) => void;
};

export function TreeNodeItem({
  node,
  depth,
  selectedId,
  onSelect,
}: TreeNodeItemProps) {
  // 节点级状态：管理自身节点的展开/收起
  const [expanded, setExpanded] = useState<boolean>(true);
  const hasChildren = node.children.length > 0;
  const isSelected = selectedId === node.id;

  return (
    <div>
      {/* 节点单行容器 */}
      <div
        className={`flex items-center gap-1 rounded px-2 py-1 text-sm transition-colors ${
          isSelected
            ? "bg-blue-600 text-white"
            : "text-gray-700 hover:bg-gray-100"
        }`}
        style={{
          // 根据层级 depth 动态计算缩进距离
          paddingLeft: 8 + depth * 16,
        }}
      >
        {/* 展开/收起切换按钮 */}
        {hasChildren ? (
          <button
            type="button"
            className="w-4 text-center text-xs opacity-70 hover:opacity-100"
            onClick={() => setExpanded((v) => !v)}
          >
            {expanded ? "▾" : "▸"}
          </button>
        ) : (
          <span className="w-4" />
        )}

        {/* 部门名称与选中点击 */}
        <button
          type="button"
          className="flex-1 truncate text-left"
          onClick={() => onSelect(node.id)}
        >
          {node.name}
        </button>
      </div>

      {/* 递归渲染子节点：仅当展开且存在子节点时渲染 */}
      {expanded &&
        hasChildren &&
        node.children.map((child) => (
          <TreeNodeItem
            key={child.id}
            node={child}
            depth={depth + 1} // 深度递增，实现视觉缩进
            selectedId={selectedId}
            onSelect={onSelect}
          />
        ))}
    </div>
  );
}

```

> 小提示：`TreeNodeItem` 自身用到了 `useState`，但它是被客户端组件 `DeptWorkspace` 引入的，已经处在客户端边界之内，所以顶部的 `"use client"` 严格来说是可以省略的。这里保留它，是为了让“哪些是客户端组件”一眼可见。
